# 1. Bản chất của RDS

	Định nghĩa

	RDS (Relational Database Service) là dịch vụ quản lý Cơ sở dữ liệu quan hệ (Relational Database).
	Nó lưu dữ liệu theo:
		Table
		Row
		Column

	và các bảng có thể liên kết với nhau bằng:
		Primary Key
		Foreign Key
		JOIN

	Ví dụ

		Customer

		ID
		Name

		Order

		ID
		CustomerID
		Price



	Có thể JOIN

	Customer
		  |
		  |
		  V
	Order

	AWS quản lý:
		Backup
		Patch
		Monitoring
		Multi AZ
		Failover

	Bạn chỉ cần dùng database.



# Bản chất

	RDS sinh ra để giải quyết:
		"Dữ liệu có mối quan hệ với nhau."



Ví dụ

		Một ngân hàng
			Khách hàng
			↓
			Tài khoản
			↓
			Giao dịch
			↓
			Lịch sử

		Tất cả đều liên quan.

		Muốn lấy:
			Tên khách
			+
			Số dư
			+
			10 giao dịch gần nhất
			→ cần JOIN

		Đó là thế mạnh của RDS.




# Ví dụ đời thường

		Một trường đại học.
			Sinh viên
			↓
			Lớp học
			↓
			Môn học
			↓
			Điểm

		Nếu dùng Excel tách riêng thì rất khó.
		Quan hệ giữa các bảng mới quan trọng.
		Đó là RDS.




# AWS Mapping


	RDS hỗ trợ
		MySQL
		PostgreSQL
		MariaDB

		SQL Server

	và Aurora.




# 2. Bản chất của DynamoDB

	Định nghĩa

	DynamoDB là
		NoSQL Key-Value / Document Database

	Không cần schema cố định.
	Không có JOIN.
	Không có Foreign Key.
	Không quan tâm quan hệ.



	Ví dụ

	User
		{
		id:100
		name:"Bao"
		level:300
		pet:"Dragon"
		gold:500000
		inventory:[...]
		}

	Một object lớn.
	Không cần chia bảng.



# Bản chất

	DynamoDB sinh ra để giải quyết
	"Lấy dữ liệu cực nhanh."
	Không phải:
	"Quan hệ dữ liệu."
	Ví dụ
	Game Online
	Player 100
	Muốn lấy
	Player 100
	Trong vài ms.
	Không cần JOIN.
	Không cần Transaction phức tạp.
	Đó là DynamoDB.



# Ví dụ thực tế


	TikTok
		Khi mở app.
		Server cần
		User ID
		↓
		Profile
		↓
		Follower
		↓
		Like
		↓
		Setting
		Chỉ cần
		GET USER 100
		Xong.
		Không cần JOIN.
		Đó là DynamoDB.




# So sánh bản chất

| RDS             | DynamoDB                |
| --------------- | ----------------------- |
| SQL             | NoSQL                   |
| Quan hệ dữ liệu | Không quan hệ           |
| JOIN            | Không JOIN              |
| Schema cố định  | Schema linh hoạt        |
| ACID mạnh       | Tối ưu tốc độ và scale  |
| Vertical Scale  | Horizontal Scale        |
| Phù hợp ERP     | Phù hợp Web/Game/Mobile |





# 3. Trade-off

	RDS

	Ưu điểm
		✔ JOIN

		✔ Transaction

		✔ Foreign Key

		✔ SQL mạnh

	Nhược điểm
		Scale khó hơn
		Phải thiết kế schema
		Không phù hợp hàng chục triệu request/s.



	DynamoDB

		Ưu điểm
			✔ Scale gần như vô hạn
			✔ Single-digit ms
			✔ Serverless
			✔ Không cần quản lý server

		Nhược điểm

		Không JOIN
		Thiết kế Access Pattern trước
		Query bị giới hạn hơn SQL

# 5. Access Pattern (Điểm rất quan trọng của DynamoDB 


	Người mới thường nghĩ:

		Thiết kế Table
		↓
		Viết Query

		Sai.

		DynamoDB làm ngược lại.

		Query trước
		↓
		Thiết kế Table sau


		Bạn sẽ hỏi:

		Lấy User theo ID
		↓
		Lấy Order theo UserID
		↓
		Lấy 20 đơn gần nhất

		Từ đó mới thiết kế:
			Partition Key
			Sort Key
			GSI
			LSI

		Đây là tư duy hoàn toàn khác RDS.
