Lesson 3 -- Simple Types -//


# 1. TypeScript là gì và tại sao cần kiểu dữ liệu? 
	TypeScript là một phiên bản nâng cấp của JavaScript, thêm vào hệ thống kiểu dữ liệu tĩnh (static types) để giúp code dễ đọc, dễ bảo trì và giảm lỗi. Kiểu dữ liệu (types) giúp xác định rõ ràng dữ liệu bạn đang làm việc (số, chuỗi, mảng, v.v.) và phát hiện lỗi ngay trong lúc viết code thay vì khi chạy chương trình.
	
# 	2. Các kiểu đơn giản (Simple Types) trong TypeScript 
	TypeScript hỗ trợ nhiều kiểu dữ liệu cơ bản, dưới đây là các kiểu chính được đề cập trong bài:
	
	
	## a. boolean 
		Mô tả: Kiểu dữ liệu chỉ nhận giá trị true hoặc false.
		Ví dụ: 
			let isDone: boolean = false;
			
		Biến isDone chỉ được gán giá trị true hoặc false. Nếu bạn cố gán giá trị khác (như số hoặc chuỗi), TypeScript sẽ báo lỗi.	
	
	
	## b. number 
		Mô tả: Biểu diễn số, bao gồm số nguyên và số thực (hỗ trợ cả thập phân, hex, binary, octal).
		Ví dụ:
		
let decimal: number = 6;
let hex: number = 0xf00d; // Hệ 16
let binary: number = 0b1010; // Hệ nhị phân
		
		Tất cả các giá trị số đều thuộc kiểu number, không phân biệt số nguyên hay số thực.
		
		
	
	## c. string 
		Mô tả: Biểu diễn chuỗi ký tự, dùng dấu nháy đơn (') hoặc nháy kép (") hoặc template literals (`).
		Ví dụ:
			
let color: string = "blue";
let fullName: string = `John Doe`;
let sentence: string = `My name is ${fullName}`; // Template literal	

		Chuỗi có thể chứa văn bản hoặc kết hợp biến bằng template literals.
	
	
	## d. array
		Mô tả: Biểu diễn danh sách các phần tử cùng kiểu. Có hai cách khai báo:
			1. type[]: Dùng dấu ngoặc vuông. 
			2. Array<type>: Dùng generic.
	
		Ví dụ: 
		
let list1: number[] = [1, 2, 3];
let list2: Array<number> = [1, 2, 3];
	
		Cả hai cách đều đảm bảo mảng chỉ chứa số. Nếu bạn thêm chuỗi vào mảng này, TypeScript sẽ báo lỗi.




	## e. tuple 
		Mô tả: Một mảng có số lượng phần tử cố định và mỗi phần tử có kiểu cụ thể.
		Ví dụ: 
			
let x: [string, number];
x = ["hello", 10]; // Đúng
x = [10, "hello"]; // Sai, vì thứ tự kiểu không khớp

	Tuple giới hạn số lượng và kiểu của các phần tử, rất hữu ích khi bạn muốn biểu diễn dữ liệu có cấu trúc cố định.




	## f. enum 
		Mô tả: Cho phép định nghĩa một tập hợp các giá trị có tên, thường dùng để biểu diễn các hằng số có ý nghĩa.
		
		Ví dụ: 
			
enum Color {
  Red, // 0
  Green, // 1
  Blue // 2
}
let c: Color = Color.Green; // c = 1

	Enum giúp code dễ đọc hơn, thay vì dùng số "vô hồn" (như 0, 1, 2), bạn dùng tên như Red, Green.
	Có thể gán giá trị cụ thể:	

enum Color {
  Red = 1,
  Green = 3,
  Blue = 5
}





	## g. any 
		Mô tả: Kiểu "bỏ qua kiểm tra kiểu", cho phép biến nhận bất kỳ giá trị nào.
		Ví dụ: 
			
let notSure: any = 4;
notSure = "maybe a string"; // Không lỗi
notSure = false; // Không lỗi
		any hữu ích khi bạn không chắc về kiểu dữ liệu (ví dụ: dữ liệu từ API), nhưng nên hạn chế dùng vì nó làm mất lợi ích của TypeScript.
		
		

	## h. void 
		Mô tả: Biểu thị hàm không trả về giá trị gì.
		
		Ví dụ : 
function warnUser(): void {
  console.log("This is a warning");
}
		void thường dùng cho hàm chỉ thực hiện tác vụ mà không return.
		
		
		
		
	## 	i. null và undefined 
		Mô tả: Hai kiểu này biểu diễn giá trị "không có giá trị" hoặc "chưa được gán".
		
let u: undefined = undefined;
let n: null = null;	
		
		Thường được dùng trong các trường hợp cần kiểm soát giá trị rỗng.
		
		
		
	## 	j. never
		Mô tả: Biểu diễn giá trị không bao giờ xảy ra, ví dụ hàm luôn throw lỗi hoặc vòng lặp vô hạn.
		
		Ví dụ : 
			
function error(message: string): never {
  throw new Error(message);
}	
	
		never ít gặp nhưng quan trọng trong các trường hợp phân tích logic code.
	
	
	## k. object
		Mô tả: Biểu diễn mọi giá trị không phải kiểu nguyên thủy (number, string, boolean, null, undefined, symbol).
		Ví dụ:
			let obj: object = { name: "John" };
			
		Dùng để chỉ các đối tượng nói chung, nhưng không cụ thể về cấu trúc.	
	
	
	
	
	
	
# 	3. Type Assertions (Ép kiểu)
		TypeScript cho phép bạn "ép kiểu" để nói với trình biên dịch rằng bạn chắc chắn về kiểu của một biến.
		
		Ví dụ:
		
let someValue: any = "this is a string";
let strLength: number = (someValue as string).length;
	
		as string hoặc <string>someValue giúp TypeScript hiểu someValue là chuỗi để truy cập .length.
	



# 4. Tại sao Simple Types quan trọng?

	Kiểm soát lỗi: TypeScript phát hiện lỗi sai kiểu ngay trong lúc code (ví dụ: gán chuỗi cho biến kiểu số).
	Tăng tính rõ ràng: Kiểu dữ liệu làm code dễ đoán hơn, đặc biệt trong dự án lớn.
	Hỗ trợ công cụ: IDE như VSCode dùng thông tin kiểu để gợi ý code chính xác hơn.
	
	
# 5. Một số lưu ý thực tế 
	- Khi nào dùng any? Chỉ dùng khi bạn thực sự không biết kiểu dữ liệu (như dữ liệu từ bên ngoài). Lạm dụng any làm mất lợi ích của TypeScript.
	
	- Tuple vs Array: Tuple hữu ích khi bạn biết chính xác số lượng và kiểu của phần tử. Array linh hoạt hơn nhưng ít kiểm soát.
	
	- Enum: Rất tốt cho các tập hợp giá trị cố định (như trạng thái, vai trò, màu sắc).
	
	- Type Assertions: Dùng cẩn thận, chỉ khi bạn chắc chắn về kiểu dữ liệu, tránh lỗi runtime.


# 6. Ví dụ tổng hợp

// Kết hợp các kiểu
enum Role { Admin, User, Guest }
let user: [string, number, Role] = ["John", 25, Role.User];

function greet(name: string): void {
  console.log(`Hello, ${name}`);
}

let mixed: any = "test";
let length: number = (mixed as string).length; // Ép kiểu

console.log(user); // ["John", 25, 1]
greet("John"); // Hello, John
