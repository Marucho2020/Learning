Lesson 167 -- Thread-safe Collections & ConcurrentMap -//



# 1. Vấn đề cơ bản
	Collection mặc định (ArrayList, HashMap) → không thread-safe.
	Dùng nhiều thread đọc/ghi → race condition, corruption, hoặc deadlock nếu wrap bằng synchronized.
	
	Java cung cấp:
		Legacy: Hashtable, Vector, Collections.synchronizedMap/List → safe nhưng toàn bộ lock, chậm khi nhiều thread.
		Modern: java.util.concurrent.* → fine-grained lock / lock-free, performance cao.



# 2. ConcurrentHashMap

	## Nguyên lý 
		Không lock toàn bộ map mà lock theo bucket / segment (Java 8+ dùng CAS + bin lock + treeify):
		
		Đọc gần như không block (volatile read).
		Viết:
			- CAS nếu bucket rỗng.
			- Nếu collision → lock bin/linked list/tree, tránh lock global.

		Thread-safe nhưng performance cực tốt cho nhiều reader, ít writer → read-heavy workload.
		Iterators: weakly consistent, không throw ConcurrentModificationException.


	## Ví dụ nâng cao
ConcurrentHashMap<String, Integer> map = new ConcurrentHashMap<>();
map.compute("key", (k, v) -> (v == null) ? 1 : v + 1); // atomic update

		- compute() đảm bảo atomic per-key, tránh race mà không cần external lock.
		- Không dùng Hashtable nữa → quá nặng, lock toàn bộ map.

# 3. CopyOnWriteArrayList

	## Dùng khi read-heavy, write-hiếm: 
		Mỗi write → copy toàn bộ array → expensive.
		Read → không cần lock, iterator an toàn.		

	## Ví dụ phù hợp:
		Listener list, config snapshot, subscriber.
	
CopyOnWriteArrayList<String> list = new CopyOnWriteArrayList<>();
list.add("A"); // copy underlying array
for (String s : list) { ... } // safe read, no lock
	
		Tip senior: nếu update nhiều → tránh CopyOnWriteArrayList vì overhead, dùng Collections.synchronizedList hoặc custom lock.
	
	
	
# 4. BlockingQueue	
	Thread-safe queue, blocking on empty/full, dùng cho producer-consumer.	
	Các implement nổi bật:	
		ArrayBlockingQueue → bounded, fair option.
		LinkedBlockingQueue → unbounded hoặc bounded, performance tốt khi nhiều producer/consumer.
		PriorityBlockingQueue → queue theo priority.		
	
	Quan trọng: tự đồng bộ + không cần external lock, iterator là weakly consistent.
	
	
# 5. SynchronizedMap / SynchronizedList 

	Collections.synchronizedMap(new HashMap()) → toàn bộ access được lock.
	Iteration vẫn cần external lock:

Map<K,V> syncMap = Collections.synchronizedMap(new HashMap<>());
synchronized(syncMap) {
    for (Map.Entry<K,V> e : syncMap.entrySet()) { ... }
}

	Nhược điểm:
		- Lock toàn bộ map → performance kém.
		- Không phân đoạn fine-grained.


# 6. Best Practices / Senior Tips 

	- Dùng ConcurrentHashMap cho map đa thread, tận dụng computeIfAbsent, merge, putIfAbsent.
	- CopyOnWriteArrayList → read-heavy, write-hiếm.
	- Avoid legacy synchronized collections (Hashtable, Vector, SynchronizedMap) → performance kém.
	- Atomic updates per key → tránh external locks.
	- Beware weakly consistent iterators:
	- Iteration không throw CME nhưng không nhất thiết snapshot toàn bộ map tại 1 thời điểm.
	- BlockingQueue → producer-consumer pattern, không dùng wait/notify thủ công nữa.


# 7. Kết hợp senior-level

	## Hiểu performance trade-off: 
		- ConcurrentHashMap → high throughput, low latency.
		- SynchronizedMap → dễ code, nhưng bottleneck.
		- CopyOnWriteArrayList → read-mostly → lock-free reads.

	Biết pattern atomic per-key + compute → tránh race condition, deadlock, lock contention.

	Luôn nghĩ iteration weakly consistent, thread có thể đọc giá trị “cũ” hoặc “mới” trong quá trình duyệt.
