Lesson 212 -- Functional Orchestration (Saga Pattern) -//


# 🧠 1. Vấn đề gốc của hệ thống phân tán
	Trong hệ thống microservices:
	
		Mỗi service (Order, Payment, Shipping, Notification) đều độc lập — không có “transaction toàn cục”.

	Nếu bạn gọi tuần tự:
createOrder();
chargePayment();
shipItem();
notifyCustomer();

	→ Nếu bước 3 fail, bạn không thể rollback 1 & 2 dễ dàng.

	## Giải pháp OOP truyền thống:
		Dùng transaction manager, saga orchestrator, hoặc choreography bằng message broker.
		
		Nhưng: phức tạp, nhiều framework, coupling cao.



	## Giải pháp functional:

		Model mọi step như pure function.
		Thay rollback = compensate, và compose chúng như pipeline.
		

# ⚙️ 2. Functional Saga Core Concept

	## a. Function kiểu Saga Step
		Mỗi bước là một function:
		Function<Input, Either<Error, Output>>
	
	Nếu thành công → trả Right(Output)
	Nếu thất bại → trả Left(Error)

	Đây chính là kiểu dữ liệu “sống còn” của functional error handling.


# b. Higher-Order Function compensate(fn, rollbackFn)

	Ta gói mỗi bước bằng một compensation function (rollback function).
		
<T, R> SagaStep<T, R> compensate(
        Function<T, Either<Error, R>> action,
        Consumer<R> rollbackFn
) {
    return new SagaStep<>(action, rollbackFn);
}


# c. Compose pipeline Saga
	Giờ ta có thể compose các step:
	
	
SagaStep<OrderRequest, Order> createOrder = compensate(
    req -> Right(orderRepo.create(req)),
    order -> orderRepo.delete(order.getId())
);

SagaStep<Order, Payment> chargePayment = compensate(
    order -> paymentService.charge(order),
    payment -> paymentService.refund(payment)
);

SagaStep<Payment, Shipment> shipItem = compensate(
    payment -> shippingService.ship(payment),
    shipment -> shippingService.cancel(shipment)
);
	
	
	
	
# 	d. Orchestration Function
	
	Giờ ta viết orchestrator thuần functional:	
	
<T> Either<Error, T> runSaga(List<SagaStep<?, ?>> steps) {
    List<Object> completed = new ArrayList<>();
    for (SagaStep step : steps) {
        var result = step.action.apply(completed.isEmpty() ? null : completed.getLast());
        if (result.isLeft()) {
            // rollback in reverse
            Collections.reverse(completed);
            completed.forEach(prev -> step.rollbackFn.accept(prev));
            return Left(result.getLeft());
        }
        completed.add(result.get());
    }
    return Right((T) completed.getLast());
}
	
	
	→ Không annotation, không AOP, thuần hàm + thuần logic.
	Không có side effect ngoài những gì ta kiểm soát rõ ràng.
	
	
# 🧩 3. So sánh với OOP Saga Framework

| Khía cạnh    | OOP Saga (Spring State Machine, Camunda, Axon...) | Functional Saga                 |
| ------------ | ------------------------------------------------- | ------------------------------- |
| Orchestrator | Stateful class / XML config                       | Pure function                   |
| Compensation | Config file hoặc annotation                       | Inline function                 |
| Testing      | Mock service, test integration                    | Unit test từng function dễ dàng |
| Debug        | Workflow trace                                    | Stream log + function chain     |
| Dependency   | Framework heavy                                   | Zero dependency                 |


# 🚀 4. Ví dụ thực tế: Order → Payment → Shipping → Notification


var saga = SagaBuilder.start(createOrder)
    .then(chargePayment)
    .then(shipItem)
    .then(notifyCustomer);

	var result = saga.run(orderRequest);


if (result.isLeft()) {
    log.error("Saga failed: " + result.getLeft());
}

	## Nếu bất kỳ bước nào fail:

		- Tự động rollback theo chuỗi đã khai báo.
		- Không cần try/catch hay transaction manager.
		- Mọi rollback đều là pure function, testable, composable.



# 🧮 5. Functional Advantage

| Ưu điểm           | Giải thích                                                                       |
| ----------------- | -------------------------------------------------------------------------------- |
| ✅ Declarative     | Ta “mô tả” workflow, không “chỉ huy” từng step                                   |
| ✅ Deterministic   | Dễ test, dễ mô phỏng                                                             |
| ✅ Immutable State | Saga log có thể lưu snapshot state → replay được                                 |
| ✅ Resilient       | Dễ kết hợp với retry, timeout, fallback (bài trước)                              |
| ✅ Parallelizable  | Có thể chạy saga branches song song (chẳng hạn `notifyManager` & `updateLedger`) |



# ⚙️ 6. Enterprise Use Case

	## 💳 Payment Pipeline
		Nếu thanh toán fail → rollback đơn hàng, hủy shipment.
		Nếu shipment fail → refund payment.


	## 🧾 Ledger System
		Mỗi bước của event ledger là append-only function, rollback chỉ thêm event “reversal”, không xóa dữ liệu.
	
	## 🚚 Supply Chain
		Các service phân tán (Inventory, Shipping, Invoice) phối hợp qua functional saga → rollback logic nằm ở từng step.
