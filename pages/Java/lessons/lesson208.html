Lesson 208 -- Functional Retry, Timeout, và Circuit Breaker Core -//


# 🧩 Tổng quan: Resilience Functional là gì?


	Resilience trong hệ thống không chỉ là chống lỗi, mà là khả năng duy trì logic nhất quán khi lỗi xảy ra — không mất dữ liệu, không crash, không làm user thấy “bị lỗi”.

	Trong functional style, resilience được viết bằng Higher-Order Functions (HOF) — tức là hàm nhận hàm, trả hàm.



# ⚙️ 1️⃣ Retry — Functional Recursive Retry

	✅ Ý tưởng
		Thay vì try-catch + vòng for, ta tạo một function bọc quanh logic gốc, có thể retry n lần nếu lỗi.
		
import java.util.function.Supplier;

public static <T> T withRetry(Supplier<T> fn, int retries) {
    try {
        return fn.get();
    } catch (Exception e) {
        if (retries > 0) {
            System.out.println("Retrying... attempts left: " + retries);
            return withRetry(fn, retries - 1);
        }
        throw e; // hết retries → ném lỗi ra
    }
}


	##🔍 Giải thích:  

		Supplier<T> đại diện cho logic “có thể thất bại”.
		
		Function withRetry là Higher-Order Function — nó không biết logic bên trong là gì (API call, DB query, hay gửi mail), chỉ xử lý cách retry.
		
		Không dùng vòng lặp hay state ngoài → pure recursion.
		
		Functional → có thể compose với withTimeout hay withCircuitBreaker.


	## 🏢 Enterprise: 

		Supplier<Response> callApi = () -> httpClient.post("/payment", payload);
		Response res = withRetry(callApi, 3);

	→ Retry 3 lần nếu HTTP call lỗi.
	Không cần @Retryable, không phụ thuộc framework.



# ⚙️ 2️⃣ Timeout — CompletableFuture Timeout Wrapper

	# ✅ Ý tưởng:
		Nếu một function mất quá lâu, ta cần giới hạn thời gian thực thi — tránh block thread hoặc treo pipeline.

import java.util.concurrent.*;

public static <T> T withTimeout(Supplier<T> fn, Duration timeout) {
    ExecutorService executor = Executors.newSingleThreadExecutor();
    Future<T> future = executor.submit(fn::get);
    try {
        return future.get(timeout.toMillis(), TimeUnit.MILLISECONDS);
    } catch (TimeoutException e) {
        throw new RuntimeException("Operation timed out", e);
    } catch (Exception e) {
        throw new RuntimeException(e);
    } finally {
        executor.shutdown();
    }
}



	CompletableFuture hoặc ExecutorService cho phép giới hạn thời gian.
	Không block main thread.
	Functional vì: withTimeout chỉ bọc function, không can thiệp logic bên trong.
	Dễ compose:
		withRetry(() -> withTimeout(apiCall, Duration.ofSeconds(2)), 3);
	→ Retry tối đa 3 lần, mỗi lần timeout 2 giây.



# ⚙️ 3️⃣ Circuit Breaker — Functional State Control

	✅ Ý tưởng
		Khi service downstream lỗi quá nhiều → “ngắt mạch” tạm thời (open state), để không làm hệ thống sập dây chuyền.

import java.util.concurrent.atomic.AtomicReference;
import java.time.Instant;

enum State { CLOSED, OPEN, HALF_OPEN }

class CircuitBreaker {
    private final AtomicReference<State> state = new AtomicReference<>(State.CLOSED);
    private final int failureThreshold;
    private final Duration openDuration;
    private Instant lastFailureTime = Instant.MIN;

    CircuitBreaker(int failureThreshold, Duration openDuration) {
        this.failureThreshold = failureThreshold;
        this.openDuration = openDuration;
    }

    public <T> T call(Supplier<T> fn) {
        if (state.get() == State.OPEN && Instant.now().isBefore(lastFailureTime.plus(openDuration))) {
            throw new RuntimeException("Circuit is open");
        }

        try {
            T result = fn.get();
            state.set(State.CLOSED); // success → reset
            return result;
        } catch (Exception e) {
            lastFailureTime = Instant.now();
            state.set(State.OPEN);
            throw new RuntimeException("Circuit opened", e);
        }
    }
}

	
	AtomicReference<State> đảm bảo thread-safe mà vẫn functional immutable style (copy-on-update).
	Không thay đổi fn bên trong, chỉ bao quanh nó.
	Có thể kết hợp withRetry và withTimeout:

CircuitBreaker breaker = new CircuitBreaker(3, Duration.ofSeconds(10));
Response res = breaker.call(() -> withRetry(() -> withTimeout(apiCall, Duration.ofSeconds(2)), 2));


# 🔗 Tổng hợp: Composable Resilience Pipeline

Supplier<Response> resilientCall =
    () -> withRetry(
            () -> withTimeout(
                    () -> breaker.call(apiCall),
                    Duration.ofSeconds(2)),
            3);

Response res = resilientCall.get();


	Code pure functional — không phụ thuộc Spring hay annotation.
	Dễ test, dễ log, dễ compose.
	Giữ logic rõ ràng: Retry → Timeout → Breaker → API call.





# 🏭 Ứng dụng Enterprise thực tế:

| Tình huống                     | Giải pháp Functional   |
| ------------------------------ | ---------------------- |
| Gọi Payment API có thể lỗi tạm | `withRetry()`          |
| Email server chậm phản hồi     | `withTimeout()`        |
| External API sập               | `withCircuitBreaker()` |
| Hệ thống messaging             | Compose cả 3 function  |



	## Khi triển khai, có thể dùng functional DSL:
	
ResiliencePolicy policy = ResiliencePolicy
    .retry(3)
    .timeout(Duration.ofSeconds(2))
    .circuitBreaker(5, Duration.ofSeconds(10));

policy.apply(apiCall);
