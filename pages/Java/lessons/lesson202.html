Lesson 202 -- Lazy Evaluation & Stream Fusion -//


# 🎯 MỤC TIÊU

1.Lazy Evaluation (遅延評価 / trì hoãn đánh giá)
→ Không tính toán cho đến khi thật sự cần kết quả.

2.Stream Fusion (ストリーム融合 / hợp nhất dòng xử lý)
→ JVM hợp nhất nhiều bước trung gian (map/filter…) thành một lần duyệt dữ liệu duy nhất — giảm overhead, tăng cache locality.



# 🧠 1. Lazy Evaluation — “Không chạy cho đến khi bị ép chạy”

	Trong Java Stream:

Stream.of(1, 2, 3, 4)
    .filter(x -> {
        System.out.println("filter: " + x);
        return x % 2 == 0;
    })
    .map(x -> {
        System.out.println("map: " + x);
        return x * 10;
    });

	👉 Không có gì in ra cả.
	Khi ta thêm .collect(Collectors.toList()):

filter: 1
filter: 2
map: 2
filter: 3
filter: 4
map: 4

→ Dòng chỉ chạy khi gặp terminal op (như collect, forEach, findFirst, reduce, v.v.)


# 🧩 Vì sao Lazy quan trọng?


	1.Tránh tính toán thừa: chỉ xử lý đến khi đủ điều kiện.
	→ Ví dụ findFirst() sẽ dừng ngay khi tìm thấy phần tử đầu tiên.
	
	2.Cho phép short-circuit (dừng sớm).
	→ anyMatch(), allMatch(), noneMatch() là những “short-circuit terminal ops”.
	
	3.Cải thiện performance cực mạnh với data lớn hoặc infinite stream (vô hạn).



# ⚙️ 2. Stream Fusion — “Gộp pipeline thành một pass”

Stream.of(1, 2, 3, 4, 5)
    .filter(x -> x % 2 == 0)
    .map(x -> x * 10)
    .forEach(System.out::println);



	Ta có 2 intermediate operations (filter, map).
	Nếu chạy theo cách naïve (ngây thơ) kiểu OOP:

		Filter tạo danh sách tạm [2, 4]
		Map lại tạo danh sách [20, 40]
		ForEach in ra
		→ Tức là duyệt 3 lần danh sách.

	## Nhưng Stream API thì khác.
	⚡ JVM thực hiện Fusion:

for (int x : data) {
    if (x % 2 == 0) {
        int y = x * 10;
        System.out.println(y);
    }
}

	Không tạo danh sách tạm trung gian, không copy dữ liệu, không cache tạm — tất cả “fused” vào cùng một loop.
	
	→ Đây chính là Stream Fusion Optimization.


# 🔍 3. Tác dụng thực tế trong Enterprise

| Ứng dụng                                | Lợi ích từ Lazy + Fusion                                                      |
| --------------------------------------- | ----------------------------------------------------------------------------- |
| **Big Data Processing**                 | Không load toàn bộ dataset vào memory, chỉ xử lý theo luồng (streaming).      |
| **Reactive Streams (Reactor / RxJava)** | Mỗi bước được “chạy lười” (lazy) cho đến khi subscriber yêu cầu.              |
| **ETL Pipelines**                       | Tránh tạo file / list trung gian, tăng throughput.                            |
| **Security Audit Stream**               | Có thể short-circuit khi gặp lỗi nghiêm trọng mà không cần duyệt toàn bộ log. |



# 🧩 4. Ví dụ thực tế — Audit Stream

List<AuditEvent> events = fetchEvents();

boolean hasCriticalIssue = events.stream()
    .filter(e -> e.getLevel() >= 3)
    .peek(e -> log.debug("Checking " + e))
    .anyMatch(AuditEvent::isCritical);


	.filter + .peek + .anyMatch
	đều fused lại thành một loop duy nhất.
	
	Khi gặp phần tử “critical” đầu tiên,
	pipeline dừng ngay (short-circuit).
	
	Không duyệt phần còn lại, không log thêm, cực nhanh.


	

# 🧠 5. Kết hợp với Parallel Stream

	Lazy evaluation và stream fusion vẫn hoạt động khi dùng song song:

employees.parallelStream()
    .filter(Employee::isActive)
    .map(Employee::getSalary)
    .reduce(BigDecimal.ZERO, BigDecimal::add);


	→ JVM chia nhỏ stream theo thread,
nhưng mỗi “substream” vẫn fused — không tạo intermediate collection.


# 🔬 6. So sánh tư duy Functional vs OOP

| Kiểu                    | Mô tả                              | Hậu quả                        |
| ----------------------- | ---------------------------------- | ------------------------------ |
| **OOP**                 | Gọi hàm là *thực thi ngay*         | Tốn tài nguyên, dễ side-effect |
| **Functional**          | Gọi hàm là *tạo pipeline chờ chạy* | Lazy, dễ tối ưu, dễ test       |
| **Imperative loop**     | Nhiều biến tạm                     | Không fusion được              |
| **Functional pipeline** | Không biến tạm, có fusion          | Cache locality cao, ít GC      |



# 🧩 7. Cơ chế bên trong JVM


Stream API dùng các Spliterator và Sink chain để thực hiện fusion.

	- Mỗi map, filter, flatMap tạo ra một lớp “Sink” nội bộ.
	- Khi terminal operation gọi evaluate(), tất cả sink được liên kết thành chuỗi duy nhất.
	- Dữ liệu đi qua “pipeline fused” này → duyệt đúng một lần duy nhất.

	filter → map → collect không phải 3 loop, mà là 1 loop nối liền nhau trong bytecode runtime.



# 🧠 8. Triết lý Functional đằng sau

Functional Design không quan tâm “chạy như thế nào” —
mà chỉ quan tâm “khi nào cần thì mới chạy”.

“Declare what you want, not how to get it.”
— triết lý cốt lõi của lazy evaluation.




# ⚡ 9. Enterprise Optimization Pattern

logs.stream()
    .filter(Log::isRelevant)
    .map(Log::extractMessage)
    .map(String::toLowerCase)
    .filter(msg -> msg.contains("error"))
    .findFirst();

	Tưởng rằng phải duyệt 1 triệu dòng?
Thực tế — JVM fusion tất cả step này, dừng ngay khi tìm thấy "error" đầu tiên.

	Hiệu năng tăng hàng chục lần.



# 🧩 10. Kết luận

| Concept              | Ý nghĩa                                | Lợi ích                  |
| -------------------- | -------------------------------------- | ------------------------ |
| **Lazy Evaluation**  | Trì hoãn thực thi đến khi thật sự cần  | Giảm tính toán thừa      |
| **Short-circuiting** | Dừng pipeline sớm khi đủ điều kiện     | Giảm I/O và CPU          |
| **Stream Fusion**    | Gộp nhiều step thành một loop duy nhất | Giảm memory, tăng speed  |
| **Ứng dụng**         | Big data, reactive, analytics, audit   | Performance, scalability |
