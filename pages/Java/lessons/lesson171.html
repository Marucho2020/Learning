Lesson 171 -- Exchanger -//


# Khái niệm 
	🔹 Exchanger – Cơ chế trao đổi dữ liệu song phương
	Exchanger<V> là một synchronization point cho hai thread trao đổi dữ liệu trực tiếp:	
		Thread A gọi exchange(valueA) → block cho đến khi Thread B gọi exchange(valueB).
		Sau khi bắt tay, A nhận valueB, B nhận valueA.
	
	Khác với BlockingQueue (một producer, nhiều consumer, hoặc buffer nhiều phần tử), Exchanger là rendezvous point 1–1, 2 chiều.	
	
	
#	2. Cơ chế hoạt động

	Nội bộ: Exchanger dùng một arena (slot) để giữ giá trị từ thread đầu tiên.

	Khi thread thứ hai tới:
		- CAS ghép cặp hai giá trị.
		- Cả hai thread được unpark và nhận dữ liệu của đối phương.

	Có thể kèm timeout:
	
	V other = exchanger.exchange(myValue, 1, TimeUnit.SECONDS);
	Nếu hết timeout mà chưa có thread nào ghép → TimeoutException.


# 3. Use case thực tế
	
	## 	Pipeline giữa hai thread: 
		
		- Ví dụ 1 thread producer tạo buffer dữ liệu, 1 thread consumer xử lý buffer.
		- Dùng Exchanger<Buffer> để swap buffer → không cần copy.

	## Double buffering: 
		
		- Producer viết vào buffer A, consumer đọc buffer B.
		- Khi cả hai xong, gọi exchange() → swap buffer.
		- Kỹ thuật này rất tối ưu khi xử lý batch (image processing, logging, batch I/O).

	## Genetic algorithms / simulations: 
		- Hai worker thread trao đổi "population state" hoặc intermediate result định kỳ.
	

# 4. Ưu điểm vs Nhược điểm
	
	## ✅ Ưu điểm: 
		
		- Rất nhẹ, trực tiếp, không cần middle buffer.
		- Gọn cho bài toán 2-thread rendezvous.
		- Hạn chế contention vì chỉ cần 2 bên match.	
	
	
	## ⚠️ Nhược điểm / trap senior: 
		
		- Chỉ dành cho 2 thread – không phải replacement cho BlockingQueue.
		- Nếu mất cân bằng load (1 thread nhanh, 1 thread chậm) → thread nhanh block mãi.
		- Nếu lạm dụng trong hệ thống nhiều thread → dễ gây deadlock hoặc starvation.
		- Không có “buffering” → dữ liệu phải được trao đổi ngay.

	

# 5. Ví dụ senior-level: Double Buffer


class ExchangerDemo {
    static Exchanger<List<Integer>> exchanger = new Exchanger<>();

    public static void main(String[] args) {
        ExecutorService exec = Executors.newFixedThreadPool(2);

        exec.submit(() -> { // Producer
            List<Integer> buffer = new ArrayList<>();
            try {
                for (int i = 0; i < 5; i++) {
                    buffer.clear();
                    buffer.add(i);
                    System.out.println("Produced: " + buffer);
                    // swap buffer with consumer
                    buffer = exchanger.exchange(buffer);
                }
            } catch (InterruptedException e) {}
        });

        exec.submit(() -> { // Consumer
            List<Integer> buffer = new ArrayList<>();
            try {
                for (int i = 0; i < 5; i++) {
                    buffer = exchanger.exchange(buffer);
                    System.out.println("Consumed: " + buffer);
                }
            } catch (InterruptedException e) {}
        });

        exec.shutdown();
    }
}

	Cả producer và consumer sẽ liên tục hoán đổi buffer.
	Không cần lock, không cần copy dữ liệu.



# 6. So sánh với các pattern khác


| Công cụ            | Đặc điểm          | Khi nào dùng                                         |
| ------------------ | ----------------- | ---------------------------------------------------- |
| `BlockingQueue`    | 1-N, có buffer    | Khi nhiều producer/consumer, decoupling tốc độ       |
| `SynchronousQueue` | 1-1, không buffer | Producer/consumer bắt tay trực tiếp, không giữ state |
| `Exchanger`        | 1-1, **2 chiều**  | Khi cần **swap dữ liệu** giữa 2 threads              |



# 7. Best practices (senior mindset)

	## Dùng Exchanger khi: 
	
		Bạn biết chắc chỉ có 2 threads làm việc cùng nhau.
		Bài toán có double-buffering / swapping dữ liệu.
		
	## Tránh dùng khi: 
		Có nhiều producer/consumer → chuyển sang BlockingQueue.
		Thread speed imbalance lớn → dễ block vô thời hạn.		


	Luôn consider timeout để tránh deadlock ẩn.

Exchanger là point-to-point data swapper, cực kỳ hiệu quả cho 2-thread pipelines (double buffering, batch handoff). Nhưng nó không scale và rất dễ trở thành bottleneck nếu thiết kế sai. Đây là tool dành cho case đặc thù, không phải vũ khí chung như BlockingQueue hay ConcurrentHashMap.
