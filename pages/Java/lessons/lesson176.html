Lesson 176 -- callback- method - fallback -//


# 🔹 1. method (phương thức bình thường)

	Definition: khối logic có input/output, gọi xong thì trả kết quả (hoặc exception).
	
	Flow: synchronous, caller kiểm soát luồng.
	
	Error handling: dùng try/catch hoặc checked/unchecked exceptions.

👉 Dùng khi: logic tuyến tính, đồng bộ, lỗi được ném trực tiếp về caller.




# 🔹 2. callback (hàm gọi ngược)

	Definition: bạn truyền một function/hàm/lambda vào API, API sẽ gọi ngược lại khi event/async task xong.
	
	Flow: control flow inverted (Inversion of Control). Caller không quyết định khi nào chạy → callee quyết định.

	Error handling: lỗi thường propagate qua callback hoặc Future/CompletableFuture.

CompletableFuture.supplyAsync(() -> fetchData())
    .thenAccept(result -> System.out.println("Got: " + result))
    .exceptionally(ex -> { 
        System.err.println("Error: " + ex); 
        return null; 
    });


	Ở đây, thenAccept và exceptionally chính là callback.
	
	👉 Dùng khi:

		- Code bất đồng bộ (I/O, network, task background).
		- Event-driven (UI, reactive systems).
		- Bạn muốn non-blocking execution.
		
		
#🔹 3. fallback (phương án thay thế khi fail) 		
		
	Definition: cơ chế degrade gracefully. Nếu main method thất bại (timeout, exception), hệ thống gọi fallback method để trả về kết quả thay thế.	
		
	Flow: vẫn synchronous hoặc asynchronous tùy implementation, nhưng luôn có default path khi main path fail.	
		
	Error handling: thay vì throw exception lên caller, bạn convert nó thành một response từ fallback.	
		
	Ví dụ (Spring Cloud Resilience4j / Hystrix style):	
		
public String getUserProfile(String id) {
    return Try.of(() -> userService.fetchProfile(id))
              .recover(ex -> defaultProfile(id))  // fallback
              .get();
}
		
		
	👉 Dùng khi:	
Distributed systems, microservices.

Tránh propagation của lỗi, tăng resilience.

Khi yêu cầu tính sẵn sàng > tính chính xác (ví dụ: search service down → trả về cached result).		
		
		
# 🔹 So sánh trọng tâm		


| Khía cạnh          | Method                  | Callback                       | Fallback                             |
| ------------------ | ----------------------- | ------------------------------ | ------------------------------------ |
| **Control flow**   | Caller quyết định       | Callee quyết định khi nào chạy | Caller gọi, nếu fail → fallback chạy |
| **Đồng bộ**        | Thường sync             | Thường async/non-blocking      | Cả sync/async                        |
| **Error handling** | throw exception         | propagate qua callback         | chuyển sang logic thay thế           |
| **Use case**       | Business logic đơn giản | Event-driven, async            | Fault tolerance, resilience          |


# 🔹 Mindset Senior

	Method = "logic core" → dùng khi deterministic và đồng bộ.
	
	Callback = "event reaction" → dùng khi inversion of control / async.
	
	Fallback = "Plan B" → dùng khi resilience, degrade gracefully.


	Trong một hệ thống microservices enterprise:

		- Method là core logic.
		- Callback xuất hiện trong messaging (Kafka consumer, HTTP async client).
		- Fallback nằm trong resilience layer (Resilience4j, Hystrix, Polly).



# 👉 Ví dụ thực chiến: 

	## Giả sử bạn có một service gọi API từ bên ngoài:

public CompletableFuture<User> getUser(String id) {
    return httpClient.fetchAsync("/users/" + id)
        .thenApply(response -> parseUser(response))     // callback
        .exceptionally(ex -> cachedUser(id));           // fallback
}

	- fetchAsync → method call async.
	- thenApply → callback khi response về.
	- exceptionally → fallback khi API fail.
