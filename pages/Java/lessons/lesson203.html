Lesson 203 -- Functional State & Event Sourcing -//


# 🧠 1. Tư duy Functional về State

	Trong lập trình hướng đối tượng (OOP), state thường là thuộc tính của object, ví dụ:

class Account {
    BigDecimal balance;

    void deposit(BigDecimal amount) {
        this.balance = this.balance.add(amount);
    }
}

	→ Ở đây, state bị thay đổi trực tiếp (mutable).
	Điều này dễ hiểu, nhưng cũng dễ gây bug, race condition, rollback khó, audit khó.

	Functional approach không cho phép mutate state, mà tạo state mới dựa trên event.

	Ví dụ functional:

		record Account(BigDecimal balance) {}
		
		record Deposit(BigDecimal amount) {}
		
		Function<Account, Function<Deposit, Account>> applyDeposit =
				acc -> dep -> new Account(acc.balance().add(dep.amount()));
		
		
		→ Mỗi event (Deposit) tạo ra một bản state mới, không đụng đến state cũ.



# ⚙️ 2. Event Sourcing — Functionalized State Management

	## 2.1 Nguyên tắc cốt lõi:
		“State hiện tại chỉ là kết quả của tất cả event đã xảy ra trước đó.”

	Tức là thay vì lưu state cuối cùng, ta lưu danh sách event bất biến:
		AccountCreated(100)
		Deposit(50)
		Withdraw(20)

	Từ đó, ta có thể tái tạo state bằng pure function:

Account initial = new Account(BigDecimal.ZERO);
List<Event> events = List.of(new Deposit(100), new Withdraw(40));

Account finalState = events.stream()
    .reduce(initial, (state, event) -> applyEvent(state, event), (a, b) -> b);


	## Mỗi applyEvent là pure function:

Account applyEvent(Account state, Event event) {
    if (event instanceof Deposit d) return new Account(state.balance().add(d.amount()));
    if (event instanceof Withdraw w) return new Account(state.balance().subtract(w.amount()));
    return state;
}

	→ Kết quả giống hệt database snapshot, nhưng không cần mutate bất cứ thứ gì.


# 🏢 3. Enterprise Application — CQRS & Ledger

	Trong enterprise, mô hình này là nền tảng của các hệ thống tài chính, audit, blockchain, và reactive domain.


	## 🔹 CQRS (Command Query Responsibility Segregation)
		“Command” (ghi) xử lý event và lưu vào event store (append-only).
		
		“Query” (đọc) tạo view model (snapshot) từ event history.

	## Functional style rất hợp với CQRS vì:
		
			Mỗi command → một pure function state + command → event.
			Mỗi event → một pure function state + event → newState.


	## Ví dụ domain banking:

Event handleCommand(AccountState state, Command cmd) {
    if (cmd instanceof DepositCommand dc)
        return new DepositedEvent(dc.amount());
    if (cmd instanceof WithdrawCommand wc && state.balance().compareTo(wc.amount()) >= 0)
        return new WithdrawnEvent(wc.amount());
    throw new IllegalStateException("Insufficient funds");
}


	→ Pure, deterministic, dễ test và dễ song song hóa.



# 🧩 4. Ưu điểm của Functional State


| Vấn đề                | OOP Layered Approach   | Functional Event Sourcing      |
| --------------------- | ---------------------- | ------------------------------ |
| **Concurrency**       | Khó, vì mutate state   | Dễ, vì append-only             |
| **Auditability**      | Cần log thủ công       | Log có sẵn qua events          |
| **Rollback / Replay** | Phức tạp               | Chỉ cần bỏ event hoặc replay   |
| **Testing**           | Mock DB, khó unit test | Pure function → dễ test        |
| **Performance**       | Phụ thuộc DB state     | Có thể stream events song song |




# 🧠 5. Ứng dụng trong các ngôn ngữ khác

| Ngôn ngữ          | Cách triển khai Functional State                      |
| ----------------- | ----------------------------------------------------- |
| **Scala / Akka**  | `PersistentActor` + `EventSourcedBehavior`            |
| **Haskell**       | Monad State, Event sourcing bằng pure folds           |
| **Clojure**       | Atom + transaction log bất biến                       |
| **Java (Spring)** | `EventStore` + `FunctionalReducer` (hoặc Vavr Either) |
| **Elixir**        | Process state được phục hồi từ event log              |



# 🏦 6. Trong Java Security & Compliance
	Functional state là nền tảng cho:
		Audit Trail (ghi lại mọi hành động user → pure event log)
		Access Log Immutability (dễ xác minh không bị chỉnh sửa)
		Data Provenance (nguồn gốc dữ liệu minh bạch)
		Reproducible Security Simulation (có thể replay toàn bộ event để kiểm chứng policy)


# ✅ Tóm tắt

| Concept                      | Ý nghĩa                                   |
| ---------------------------- | ----------------------------------------- |
| **State = Function(events)** | Không lưu biến, mà tính toán từ event     |
| **Pure Transition Function** | `(state, event) → newState`               |
| **Append-only Log**          | Không xóa, chỉ thêm → reliability cao     |
| **Replayability**            | Có thể rebuild bất kỳ state trong quá khứ |
| **Functional**               | Dễ test, dễ scale, dễ parallel            |
