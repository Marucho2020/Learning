Lesson 170 -- Concurrency Design Patterns & Best Practices -//


# 1. Immutable Objects 
	Nguyên tắc: Object không thay đổi sau khi khởi tạo → thread-safe “tự nhiên”.
	Lợi ích:
		Không cần lock.
		Dễ dàng share giữa threads.

final class User {
    private final String name;
    private final int age;
    public User(String name, int age) { this.name = name; this.age = age; }
    public String getName() { return name; }
    public int getAge() { return age; }
}

	Senior tip: Immutable + copy-on-write → kết hợp với functional style cho thread-safe state.
	
	
# 2. Thread Confinemen	
	Giới hạn dữ liệu/objects cho một thread → không cần lock.
	Types:	
		Stack confinement – local variable chỉ dùng trong method/thread → tự thread-safe.
		ThreadLocal – giữ state riêng cho mỗi thread, ví dụ connection pool, date formatter.
		
		private static final ThreadLocal<SimpleDateFormat> df = ThreadLocal.withInitial(() -> new SimpleDateFormat("yyyy-MM-dd"));

		Pitfall senior: nhớ remove() nếu dùng thread pool → tránh memory leak.
	
	
	
# 3. Thread Pool / Executor Pattern	
	
	Thay vì new Thread():
		- Quản lý resource tốt hơn.
		- Tái sử dụng thread → giảm overhead.	
	
	Các loại Executor:
		- FixedThreadPool → cố định, predictable.
		- CachedThreadPool → dynamic, thích hợp IO-bound.
		- ScheduledThreadPool → định kỳ.		
	
	Best practice: luôn shutdown pool, tránh leak threads.
		
	
	
# 4. Double-Checked Locking
	Pattern lazy init singleton thread-safe.

private volatile static Singleton instance;
public static Singleton getInstance() {
    if (instance == null) {
        synchronized(Singleton.class) {
            if (instance == null) instance = new Singleton();
        }
    }
    return instance;
}

	Key: volatile để tránh instruction reordering → đảm bảo instance fully constructed.


# 5. Blocking vs Non-blocking

	Blocking:
		synchronized, Lock, BlockingQueue.
		Thread chờ → tốn context switch.
		
	Non-blocking / lock-free:
		Atomic*, CAS, LongAdder, StampedLock (optimistic read).
		Thích hợp low-latency, high concurrency.


# 6. Reactive / Event-driven patterns 

	Dựa trên async event loops, không block thread.
	
	Java 9+: Flow API (Publisher/Subscriber).
	
	Phù hợp IO-bound, số lượng thread ít nhưng xử lý nhiều sự kiện.	


# 7. Livelock vs Deadlock 

	Deadlock: threads chờ nhau → block.
	
	Livelock: threads vẫn chạy, liên tục retry, nhưng không tiến triển.
	
	Senior tip:
	
		Detect patterns, dùng tryLock(timeout), atomic per-key, hoặc design retry/backoff.



# 8. Kết hợp các pattern


	Immutable + Thread confinement + Executor → tối ưu cho shared state minimal, dễ maintain.
	
	CAS / atomic + lock-free data structures → high concurrency.
	
	BlockingQueue + thread pool → producer-consumer pattern.
	
	Reactive + event loop → IO-bound, low thread count.
	
	Double-checked locking → singleton initialization.
	
	ThreadLocal → state per-thread trong pool → tránh shared mutable state.
	
	
	
	
# 	9. Senior-level mindset 
	
	Always minimize shared mutable state → immutable + confinement.
	
	Use high-level concurrency constructs first → Executors, BlockingQueue, ForkJoin, Reactive.
	
	Avoid low-level wait/notify trừ khi viết framework hoặc cần tối ưu.
	
	Detect deadlock/livelock early → diagram locks and resources.
	
	Performance tuning → balance thread count, task granularity, lock-free vs blocking.
