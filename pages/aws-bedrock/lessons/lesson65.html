Lesson 66 -- AIP-C01--= Strands Agents & AgentCore -//



	Strands Agents = framework để xây dựng logic của agent.
	Amazon Bedrock AgentCore = managed infrastructure/runtime để chạy, bảo mật, kết nối và vận hành agent.

	Đừng hiểu AgentCore là một agent framework thay thế Strands. Hai thằng nằm ở hai tầng khác nhau.

# 2. Strands Agents là gì?

	Strands là agent development framework của AWS.
	Nó cung cấp abstraction để bạn viết:

	Agent
	 ├── Model
	 ├── System prompt
	 ├── Tools
	 ├── Agent loop
	 └── State/context

	Thay vì tự viết toàn bộ:


while not finished:

    response = call_llm()

    if response.requests_tool:
        result = execute_tool()

        append_to_context(result)

    else:
        return response


	framework xử lý agent loop cho bạn.

	Về bản chất:

		User
		  │
		  ▼
		Agent
		  │
		  ├── LLM reasoning
		  │
		  ├── Tool selection
		  │
		  ├── Tool execution
		  │
		  ├── Observation
		  │
		  └── Continue / Finish

	Đây chính là phần cognitive/orchestration layer.





# 3. Strands không phải AgentCore
	Đây là trap rất dễ dính.

| Thành phần              | Vai trò                        |
| ----------------------- | ------------------------------ |
| Strands Agents          | Agent framework                |
| LangGraph               | Agent orchestration framework  |
| LangChain               | LLM/application framework      |
| CrewAI                  | Multi-agent framework          |
| AutoGen                 | Agent framework                |
| AgentCore Runtime       | Managed runtime/infrastructure |
| AgentCore Gateway       | Tool connectivity              |
| AgentCore Memory        | Agent memory                   |
| AgentCore Identity      | Identity/credentials           |
| AgentCore Observability | Observability                  |
| AgentCore Policy        | Agent/tool policy              |



	Nói cách khác:


              APPLICATION / AGENT LOGIC
                       │
       ┌───────────────┼────────────────┐
       │               │                │
    Strands        LangGraph        Custom code
       │               │                │
       └───────────────┼────────────────┘
                       │
                       ▼
             ┌──────────────────┐
             │ AgentCore Runtime│
             └──────────────────┘



	AgentCore được thiết kế để framework-agnostic.
	Đây chính là ý của:
	framework agnostic
	Nó có nghĩa là AgentCore không yêu cầu bạn phải dùng Strands.

	Bạn có thể có:
		Strands
		LangGraph
		CrewAI
		custom Python agent
		custom TypeScript agent
		...
			│
			▼
	   AgentCore Runtime






# 4. Tại sao AWS lại tách như vậy?


	Đây mới là phần đáng học.

	AWS không muốn bạn phải lựa chọn:
		"Muốn dùng AWS AgentCore thì phải dùng framework X."
		Bởi vì ecosystem agent thay đổi cực nhanh.

	Hôm nay:
		Strands

	Ngày mai:
		LangGraph

	Ngày kia:
		Custom orchestration

	Nếu infrastructure phụ thuộc chặt vào framework thì AWS tự khóa mình.

	Do đó AWS tách:
		Agent intelligence
			   ≠
		Agent infrastructure

	Đây là architecture decision rất hợp lý.

Ví dụ tool:
	get_employee_status()
	get_project_status()
	create_ticket()
	query_database()

	Agent không nhất thiết phải biết implementation phía dưới.

	Gateway có thể đứng giữa agent và tool ecosystem.




# 8. Một điểm cực kỳ quan trọng: Tool ≠ Agent


	Các tool có thể được implement bằng:
		Lambda
		API Gateway
		MCP server
		AWS service
		external SaaS
		database

	AgentCore Gateway giúp biến nhiều backend capability thành những tool mà agent có thể sử dụng.




# 9. Còn Memory?

	Đây là chỗ architecture bắt đầu giống production system thật.
	AgentCore Runtime không có nghĩa là toàn bộ state tự động nằm trong process memory.


Ví dụ:

Session A
    │
    ▼
Strands Agent
    │
    ├── reasoning
    ├── temporary context
    └── tool calls

Khi instance chết:

         X
    process memory

không nên được coi là persistent state.


	Nếu cần persistence:

	Strands Agent
		  │
		  ▼
	AgentCore Memory
		  │
		  ├── short-term
		  └── long-term

	Hoặc application-specific state:
		Aurora
		DynamoDB
		S3
		OpenSearch

	Tùy loại dữ liệu.



# 11. Multi-Agent với Strands + AgentCore

                    Supervisor
                 Strands Agent
                       │
          ┌────────────┼────────────┐
          ▼            ▼            ▼
       Agent A       Agent B      Agent C
       Research      Finance      Operations
          │            │            │
          ▼            ▼            ▼
     AgentCore     AgentCore    AgentCore
      Runtime       Runtime      Runtime


Hoặc:
	Supervisor
	   │
	   ├── A2A ──► Agent A
	   │
	   ├── A2A ──► Agent B
	   │
	   └── A2A ──► Agent C

AgentCore Runtime hỗ trợ A2A protocol cho mô hình agent-to-agent.


Đây khác hoàn toàn:
	Agent → Lambda
	vì Lambda chỉ là tool/backend capability.

Còn:
	Agent A → Agent B
	là agent collaboration.


# 12. Strands Agent Loop
	Nếu phải nhớ một thứ về Strands cho AIP-C01, hãy nhớ bản chất này:

             ┌───────────────┐
             │     User      │
             └───────┬───────┘
                     ▼
             ┌───────────────┐
             │     Agent     │
             └───────┬───────┘
                     ▼
              ┌────────────┐
              │    Model   │
              └─────┬──────┘
                    │
            decide next action
                    │
          ┌─────────┴─────────┐
          │                   │
       final answer         tool call
                              │
                              ▼
                            Tool
                              │
                              ▼
                         observation
                              │
                              └──────► Model

	Đó mới là agent loop.
Không phải cứ:
	LLM + prompt
	là agent.



# 13. Trade-off

| Tiêu chí             | Strands               | AgentCore              |
| -------------------- | --------------------- | ---------------------- |
| Agent reasoning      | ✅                     | ❌                      |
| Agent loop           | ✅                     | ❌                      |
| Tool orchestration   | ✅                     | hỗ trợ infrastructure  |
| Model integration    | ✅                     | infrastructure         |
| Runtime              | ❌                     | ✅                      |
| Scaling              | ❌                     | ✅                      |
| Identity             | ❌                     | ✅                      |
| Gateway              | ❌                     | ✅                      |
| Memory service       | ❌                     | ✅                      |
| Observability        | framework-level       | managed infrastructure |
| Policy               | application/framework | AgentCore Policy       |
| Multi-agent protocol | logic                 | Runtime A2A support    |
| Framework dependency | là framework          | framework-agnostic     |
