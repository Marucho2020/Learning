# I. Bản chất của Model Invocation

	Hãy quên API trước.
	Đầu tiên phải hiểu bản chất.
	Một Foundation Model (Claude, Llama, Nova, Titan...) chỉ biết đúng một việc:
	Nhận Input → Tính toán → Trả Output


Input
↓
Claude
↓
Output


	AWS chỉ đang tạo ra nhiều "cửa" khác nhau để bạn gửi request vào model.

	Giống như:
	Bạn muốn nói chuyện với một nhân viên.
	Có nhiều cách
		Gọi điện
		Chat
		Email
		Gặp trực tiếp

	Đều là nói với cùng một người.
	Khác nhau ở giao thức.
	Model cũng vậy.
	Claude không quan tâm bạn gọi bằng API nào.
	Bedrock sẽ chuyển đổi request.




# II. InvokeModel là gì?

	InvokeModel là API nguyên thủy (low-level API).
	Nó gần như nói với model rằng
	Đây là dữ liệu.
	Đây là prompt.
	Đây là các parameter.
	Hãy xử lý.

	Ví dụ

		App
		↓
		InvokeModel API
		↓
		Claude
		↓
		Response

	Bạn phải tự chuẩn bị toàn bộ request.
	
	
	
	Ví dụ
		{
		  "prompt":"Explain RAG",
		  "temperature":0.5,
		  "max_tokens":1000
		}

	Bedrock chỉ chuyển request.
	Không giúp gì thêm.
	Đây gần giống HTTP POST.	
		
		
		
	Đặc điểm
		Low-level
		Full control
		Phải biết format từng model
		Mỗi model có body khác nhau

	Ví dụ
	Claude
		messages
	Llama
		prompt
	Titan
		inputText

	Cùng một ý
	Nhưng JSON khác nhau.
	Đây chính là điều gây đau đầu.
		
	
	
# 	Ví dụ

	Nếu công ty đổi
		Claude
		↓
		Llama

	Developer phải sửa code.
	Bởi vì body request khác.






# III. Converse API là gì?


	Converse API sinh ra để giải quyết đúng vấn đề trên.
	AWS nói rằng
	"Tôi sẽ tạo một API thống nhất."
	Bạn không cần biết model nào.
	Bạn chỉ cần nói

	Kiến trúc
		Application
		↓
		Converse API
		↓
		Bedrock
		↓
		Claude
		↓
		Llama
		↓
		Nova
		↓
		Mistral
		↓
		Response

		Bạn không còn nói chuyện trực tiếp với model.
		Bạn nói chuyện với Bedrock.
		Bedrock phiên dịch.


	Ví dụ
		Bạn luôn gửi


{
  "messages":[
      {
        "role":"user",
        "content":[
            {
                "text":"Explain RAG"
            }
        ]
      }
  ]
}


	Nếu hôm nay

		Claude
		↓
		Bedrock dịch sang Claude Format
		Nếu mai
		Nova
		↓
		Bedrock dịch sang Nova Format
		Application KHÔNG đổi.
		Đây chính là abstraction.
			
			
	
	
# 	IV. Bản chất thật sự của Converse API
	
	
	Converse API không phải là Chat API.
	Đây là điểm AWS rất thích gài.
	Nó là
	Universal Model Invocation API

	Nó chuẩn hóa
		prompt
		message
		system
		tool use
		inference config
		streaming

	cho tất cả model.
	Chat chỉ là một use case.	
		
		
		
# 	V. So sánh	
		
	
| Tiêu chí               | InvokeModel          | Converse API  |
| ---------------------- | -------------------- | ------------- |
| Mức abstraction        | Thấp                 | Cao           |
| Phải biết format model | Có                   | Không         |
| Đổi model              | Thường phải sửa code | Hầu như không |
| Hỗ trợ multi-turn      | Tự xử lý             | Thiết kế sẵn  |
| Tool use               | Phức tạp             | Native        |
| System Prompt          | Tự theo từng model   | Chuẩn hóa     |
| AWS khuyến nghị        | Chỉ khi cần đặc thù  | Có            |

# VII. Trade-off

	## Converse 



	Ưu điểm
		Portable
		Clean Code
		Unified API
		Future Proof

	Nhược
		Không expose hết mọi tính năng đặc thù của từng model ngay lập tức.

	Ví dụ

		Nếu Anthropic ra một parameter mới.
		InvokeModel thường hỗ trợ trước.
		Converse có thể cần AWS cập nhật.



	## InvokeModel


		Ưu điểm
			Toàn quyền điều khiển.
			Có thể dùng ngay tính năng mới.

		Nhược
			Vendor-specific.
			Đổi model rất đau.

# 	X. AWS Professional Exam Scenario	
		
Một công ty đang phát triển chatbot nội bộ bằng Amazon Bedrock. Kiến trúc phải đáp ứng các yêu cầu sau:

Có thể dễ dàng chuyển đổi giữa Anthropic Claude và Amazon Nova trong tương lai.
Muốn giảm tối đa việc sửa đổi mã nguồn của ứng dụng khi thay đổi model.
Hỗ trợ hội thoại nhiều lượt (multi-turn conversation) và khả năng gọi công cụ (tool use).

Câu hỏi: Nên sử dụng API nào?

Đáp án đúng

Converse API

Lý do:

Chuẩn hóa định dạng message giữa các model.
Giảm phụ thuộc vào từng nhà cung cấp model.
Hỗ trợ thống nhất cho multi-turn conversation, system prompt, tool use và inference configuration.
Giúp thay đổi modelId mà ít hoặc không cần thay đổi cấu trúc request.		
		
		
# 	XI. Các bẫy AWS rất hay gài	
		
| Bẫy                                                       | Thực tế                                                                                                                                                            |
| --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Converse chỉ dành cho chatbot                             | Sai. Đây là API chuẩn hóa cho việc gọi nhiều loại Foundation Model.                                                                                                |
| InvokeModel đã bị deprecate                               | Sai. Vẫn được hỗ trợ và cần thiết cho một số tính năng đặc thù của model.                                                                                          |
| Converse luôn thay thế hoàn toàn InvokeModel              | Sai. Nếu cần sử dụng khả năng riêng mà Converse chưa hỗ trợ, InvokeModel vẫn là lựa chọn phù hợp.                                                                  |
| Converse nhanh hơn InvokeModel                            | Sai. Khác biệt chủ yếu nằm ở abstraction và trải nghiệm lập trình, không phải hiệu năng inference.                                                                 |
| Chuyển model bằng Converse sẽ không bao giờ phải sửa code | Sai. Thông thường chỉ cần đổi `modelId`, nhưng nếu logic ứng dụng phụ thuộc vào hành vi hoặc định dạng đầu ra riêng của từng model thì vẫn có thể phải điều chỉnh. |




# XIII. Ghi nhớ để nhớ mãi

| Hình ảnh liên tưởng                                                                                                                              | API              |
| ------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------- |
| Ổ cắm điện đa năng (universal adapter): mọi thiết bị đều cắm qua cùng một chuẩn, adapter tự chuyển đổi sang chuẩn của từng quốc gia              | **Converse API** |
| Cắm trực tiếp vào ổ điện của từng quốc gia: phải dùng đúng loại phích cắm cho từng nơi nhưng khai thác được đầy đủ khả năng của hệ thống điện đó | **InvokeModel**  |


Converse API = Chuẩn hóa (Abstraction + Portability + Maintainability).
InvokeModel = Điều khiển trực tiếp (Low-level + Model-specific + Full Feature Access).
