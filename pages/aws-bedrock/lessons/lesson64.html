Lesson 65 -- AIP-C01 --=Amazon Bedrock AgentCore Runtime -//


	Đây là một trong những thành phần quan trọng nhất để hiểu AgentCore ở mức production. Điểm cần sửa trong cách tư duy là:

	AgentCore Runtime không phải là “Agent”. Nó là execution/hosting environment để chạy Agent.

	AWS mô tả Runtime là môi trường hosting được quản lý, purpose-built cho agent/tool, framework-agnostic và model-agnostic. Nó có thể chạy agent viết bằng LangGraph, CrewAI, Strands hoặc custom code, và agent có thể sử dụng model ngoài Bedrock.

                               │

           LLM          Tools/API      Memory



	Runtime = nơi Agent được thực thi.

	Còn:
		Agent = logic reasoning + planning + tool use.
		Model = bộ não suy luận.
		Runtime = execution environment.
		Gateway = lớp expose/discover tools.
		Identity = agent được phép hành động với danh tính nào.
		Memory = trạng thái/context dài hạn.
		Observability = nhìn được agent đang làm gì.

	AWS thiết kế AgentCore thành các capability có thể dùng cùng nhau hoặc độc lập.

	Đây chính là phần agent infrastructure.
	AgentCore Runtime gom phần infrastructure đó thành một managed execution layer.
	AWS nhấn mạnh Runtime xử lý scaling, session management, security isolation và infrastructure management.

	Tư duy senior:

	Đừng hỏi:
		"AgentCore Runtime có chạy được LangGraph không?"

	Nếu không → Runtime có giá trị.



# 3. Runtime khác Lambda ở đâu? 

|                     | Lambda                       | AgentCore Runtime            |
| ------------------- | ---------------------------- | ---------------------------- |
| Mục đích chính      | Function execution           | Agent/tool hosting           |
| Execution           | Function                     | Stateful agent session       |
| Agent loop          | Bạn tự xây                   | Agent code/framework của bạn |
| Session             | Không phải abstraction chính | Core concept                 |
| Long-running        | Giới hạn Lambda              | MicroVM tới 8h               |
| Streaming           | Có cơ chế riêng              | HTTP/WebSocket               |
| Agent isolation     | Execution environment        | Session-isolated microVM     |
| Framework           | Không quan trọng             | Framework-agnostic           |
| MCP/A2A             | Tự triển khai                | Native protocol support      |
| Agent observability | Tự build nhiều phần          | Agent-aware tracing          |


	Runtime hiện hỗ trợ HTTP, MCP, A2A và AG-UI service contracts.
	Điểm quan trọng: Runtime không biến Lambda thành agent.
	Nó cung cấp hosting substrate phù hợp với lifecycle của agent.



# 4. Session là khái niệm cực kỳ quan trọng


User A
   │
   └── session-A
          │
          └── Agent Runtime
                 ├── reasoning
                 ├── tool calls
                 └── filesystem/state


User B
   │
   └── session-B
          │
          └── Agent Runtime
                 ├── reasoning
                 ├── tool calls
                 └── filesystem/state


	Với microVM, mỗi user session chạy trong một microVM riêng với CPU, memory và filesystem isolation. Khi session kết thúc, microVM bị terminate và memory được sanitised.

	Đây là một điểm rất quan trọng về multi-tenant security.


		Không nên tư duy:

		100 users
		   ↓
		1 process
		   ↓
		100 conversation variables


	mà Runtime cung cấp abstraction:

	100 users
	   ↓
	100 isolated sessions

# 	8. Compute model — cực kỳ quan trọng cho Production				
	Hiện tại Runtime có hai compute types:				
					
					
	① microVM

	Phù hợp:
		API-driven agent
		session ngắn hơn
		scale dynamically
		serverless
		lightweight workloads

	Session tối đa hiện tại: 8 giờ.					
						
					
					
	② Instances				
							
		Agent chạy trên AWS-managed EC2 infrastructure trong AWS account của bạn.

		Phù hợp:
			persistent workloads
			long-running session
			GPU
			multi-agent collaboration
			workload cần persistent compute

		Session tối đa: 14 ngày.					
							
| Requirement                    |                     microVM |            Instances |
| ------------------------------ | --------------------------: | -------------------: |
| Serverless                     |                           ✅ |                    ❌ |
| Scale on demand                |                           ✅ |                    ✅ |
| Lightweight API agent          |                           ⭐ |                      |
| Persistent compute             |                             |                    ⭐ |
| GPU                            |                           ❌ |                    ✅ |
| Multi-agent trên cùng instance |                           ❌ |                    ✅ |
| Session max                    |                          8h |              14 ngày |
| EC2 pricing mechanisms         |                           ❌ |                    ✅ |
| Operational burden             |                        thấp |              cao hơn |
| Production default             | thường là lựa chọn đầu tiên | khi workload yêu cầu |
					
	AWS cũng nói rõ: workload API-driven nhẹ, hoàn thành nhanh thường phù hợp microVM; workload dài, stateful, GPU hoặc collaboration phù hợp Instances.				
					
					
					
					
# 	9. Runtime V2 — kiến thức AWS hiện hành			
	
	Đây là phần Current AWS, rất đáng biết dù cần phân biệt với core exam knowledge.				
					
	Runtime hiện có platform version V1 và V2.

	V2 sử dụng snapshot-based startup:					
						
	Traditional:

		Start container
			  ↓
		Load image
			  ↓
		Install/init
			  ↓
		Initialize agent
			  ↓
		Ready					
								
						
	V2:

		Prepare environment
			   ↓
		Initialize
			   ↓
		Create snapshot
			   ↓
		Future session
			   ↓
		Restore snapshot
			   ↓
		Ready					
					
					
	Mục tiêu là làm cold-start nhanh và ổn định hơn, đặc biệt với image lớn hoặc bursty workloads. V2 hiện hỗ trợ cả Asia Pacific (Tokyo)				
					
	Đây là kiến thức production đáng biết:
	Đừng mặc định V1 là kiến trúc mới nhất chỉ vì documentation/example cũ vẫn dùng V1.				
					
					
				
				
# 10. Versioning — điểm rất quan trọng cho Production				
				
	AgentCore Runtime có immutable versions.	
	
		Runtime
		│
		├── Version 1
		│
		├── Version 2
		│
		├── Version 3
		│
		└── Version 4				
						
	Mỗi configuration update tạo version mới.
	Sau đó endpoint trỏ đến version:			
				
                    ┌── Version 1
                    │
Runtime ────────────┼── Version 2
                    │
                    └── Version 3
                           ▲
                           │
                      PROD endpoint				
				
				
	Điều này cho phép:
		DEV
		 ↓
		STAGING
		 ↓
		PROD

	mà không nhất thiết phải thay đổi runtime artifact đang chạy production ngay lập tức.
	AWS documentation xác nhận versions immutable và endpoints có thể reference specific versions.

# 	12. Agent loop thực sự nằm ở đâu?			
				
				
while not done:

    context = build_context()

    decision = llm(context)

    if decision.requires_tool:
        result = execute_tool(decision.tool)
        context.append(result)

    else:
        return decision.answer				
				
				
	Đây là agent loop.
		Runtime không phải bản thân loop.
		Runtime cung cấp nơi để loop đó chạy:

# 	14. Security			
					
					
	Một điểm rất đáng chú ý:
		Runtime có session isolation.

	Nhưng đừng nhầm:

		Runtime isolation
			   ≠
		Authorization

	Ví dụ:

		User A
		   ↓
		Agent Runtime
		   ↓
		Tool: DELETE_CUSTOMER

	Runtime isolation không tự quyết định:
		User A có được phép delete customer hay không?

	Cái này liên quan tới:

		Identity
		IAM
		Authorization
		Policy
		Tool permissions
		Application-level authorization

	Vì vậy production architecture phải có nhiều lớp:

		Authentication
			  ↓
		Identity
			  ↓
		Authorization
			  ↓
		Agent policy
			  ↓
		Tool permission
			  ↓
		Execution isolation

	Đây là tư duy security đúng.
