Lesson 28 -- AIP-C01 --=So sánh Bedrock vs SageMaker JumpStart -//

	Đây là một cặp rất dễ bị AWS gài trong AIP-C01. Điểm mấu chốt:
		Bedrock = dùng Foundation Model như một managed API để xây GenAI application.
		SageMaker JumpStart = tìm → customize → deploy các model vào hạ tầng SageMaker, với quyền kiểm soát ML cao hơn.

	AWS cũng phân biệt khá rõ: Bedrock phù hợp khi muốn tích hợp AI vào ứng dụng mà không muốn đầu tư nhiều vào custom model development; SageMaker AI phù hợp với nhu cầu training, fine-tuning và customization sâu.


# bản chất
	Hãy tưởng tượng bạn cần xây chatbot cho công ty.

	Bedrock
	Bạn nói:
		"Tôi cần Claude/Nova/Llama. AWS hãy lo phần model infrastructure. Tôi chỉ gọi API."


	Ví dụ:
		Application
			↓
		Bedrock API
			↓
		Claude / Nova / Llama / ...
			↓
		Response

	Bạn không trực tiếp quản lý GPU inference infrastructure.
	Bedrock là fully managed service cho việc truy cập các Foundation Models và xây GenAI application.


# SageMaker JumpStart

Bạn nói:
	"Tôi muốn lấy một model có sẵn, customize/deploy nó theo cách tôi kiểm soát được."


	Ví dụ:
		Developer / ML Engineer
				↓
		SageMaker JumpStart
				↓
		Select model
				↓
		Fine-tune / customize
				↓
		SageMaker Endpoint
				↓
		Application

	JumpStart cung cấp nhiều foundation model, pretrained model và solution template; model có thể được deploy thành SageMaker endpoint.



# 2. So sánh trực diện

|                              | **Amazon Bedrock**                          | **SageMaker JumpStart**                                |
| ---------------------------- | ------------------------------------------- | ------------------------------------------------------ |
| Bản chất                     | Managed GenAI service                       | Model hub/catalog trong SageMaker                      |
| Mục tiêu chính               | **Build GenAI applications**                | **Find/customize/deploy models**                       |
| Người dùng chính             | Application developer                       | Data Scientist / ML Engineer                           |
| Infrastructure               | AWS quản lý phần lớn                        | Bạn kiểm soát deployment nhiều hơn                     |
| Model selection              | Các FM được Bedrock hỗ trợ                  | Rất nhiều open/proprietary models                      |
| Fine-tuning                  | Có, nhưng theo model/capability được hỗ trợ | **Mạnh hơn, linh hoạt hơn**                            |
| Training                     | Không phải mục tiêu chính                   | **Có**                                                 |
| Custom model                 | Có một số khả năng customization/import     | **Rất linh hoạt**                                      |
| Endpoint management          | Managed inference API                       | SageMaker Endpoint                                     |
| GPU/inference infrastructure | Không cần tự quản lý                        | Có thể phải quản lý/cấu hình instance                  |
| RAG                          | Bedrock Knowledge Bases                     | Tự xây RAG hoặc kết hợp dịch vụ khác                   |
| Agents                       | **Bedrock Agents**                          | Không phải trọng tâm                                   |
| Guardrails                   | **Bedrock Guardrails**                      | Có thể tích hợp Bedrock tooling trong một số kiến trúc |
| Tool use                     | **Native Bedrock capabilities**             | Tự xây orchestration                                   |
| Operational complexity       | **Thấp hơn**                                | **Cao hơn**                                            |
| Control                      | Thấp hơn                                    | **Cao hơn**                                            |
| ML customization             | Trung bình                                  | **Rất cao**                                            |


	AWS mô tả JumpStart là nơi onboard và duy trì các foundation model công khai/proprietary để bạn access, customize và tích hợp vào ML lifecycle.




# 3. Điểm quan trọng nhất: Model ≠ Service
	Đây là chỗ rất nhiều người học AWS hiểu sai.
	SageMaker JumpStart không phải là một loại Foundation Model.

	Nó giống một:
		Model catalog + deployment/customization mechanism


	Ví dụ JumpStart có thể cung cấp model từ:
		Hugging Face
		Meta
		Stability AI
		Amazon
		Cohere
		AI21 Labs
		các model khác

	Danh sách model thay đổi theo thời gian.

# 5. Nhưng nếu requirement là:

	Lúc này:

				   ↓

	JumpStart hỗ trợ fine-tuning foundation model bằng domain-specific data; quá trình này thay đổi model weights.




# 6. Một khác biệt cực kỳ quan trọng: Control vs Convenience(tiện lợi)

	Đây là cách tôi muốn bạn nhớ cho AIP-C01:

                 CONTROL
                    ↑
                    │
          SageMaker JumpStart
                    │
                    │
                    │
                    │
              Amazon Bedrock
                    │
                    ↓
              CONVENIENCE



	## Bedrock 
		Bạn muốn:
			"Tôi không muốn trở thành ML infrastructure engineer."
			→ Bedrock.


	JumpStart
		Bạn muốn:
			"Tôi muốn kiểm soát model và ML lifecycle."
			→ SageMaker.



# 7. Nhưng đừng hiểu sai rằng JumpStart = tự quản lý tất cả


	Đây là một trap.
	JumpStart vẫn giúp triển khai model nhanh chóng. AWS cung cấp cơ chế deploy model chỉ với vài dòng SageMaker SDK.

	Và hiện nay JumpStart còn có optimized deployments giúp lựa chọn deployment configuration theo:

		- cost
		- throughput
		- latency
		- balanced performance

	và cung cấp các metric như P50 latency, TTFT và throughput trước deployment cho các model được hỗ trợ.


	Cho nên:
		JumpStart ≠ tự dựng GPU server từ số 0.

	Mà là:
		SageMaker cung cấp ML infrastructure + JumpStart giúp model selection/deployment/customization nhanh hơn.

                    │

                    │

                    │

# 11. Trap cực lớn: "Bedrock không customize được"

	❌ Sai.
		Bedrock có các capability customization/fine-tuning tùy model.

	Nhưng:
		Bedrock customization ≠ SageMaker's full ML flexibility.

	Đề thi có thể viết:
		"The company needs to fine-tune a supported foundation model..."
		→ Bedrock có thể phù hợp.

	Nhưng nếu:
		"The company requires extensive control over training infrastructure, custom training workflows, model artifacts and deployment."
		→ SageMaker.
		
		AWS Decision Guide cũng nhấn mạnh SageMaker khi workload cần extensive training, fine-tuning và customization.



# 12. Trap thứ hai: "JumpStart có nhiều model hơn → luôn chọn JumpStart"


	❌ Sai.
	Model availability chỉ là một criterion.(tiêu chí)

	Ví dụ:
		Requirement:
			Claude + RAG + Guardrails + Agents

		Không nên nghĩ:
		"JumpStart có nhiều model hơn."
		Mà phải nhìn application capability.

		→ Bedrock.

		AWS cũng lưu ý Bedrock có những proprietary models như Claude mà không có trong SageMaker JumpStart, trong khi JumpStart có portfolio rộng hơn về open/public/proprietary models.




# 13. Cách AWS ra đề

	AWS thường không hỏi:
		"What is SageMaker JumpStart?"

	Professional-level thường hỏi kiểu:
		A company wants to deploy an open-weight foundation model. The model must be fine-tuned using proprietary data. The company requires control over inference infrastructure and wants to optimize model deployment for latency and throughput. Which solution should the company use?


	Nhìn keyword:
		open-weight
			   ↓
		fine-tuning
			   ↓
		customization
			   ↓
		inference infrastructure
			   ↓
		latency / throughput optimization

	→ SageMaker JumpStart


	Ngược lại:
		A company wants to quickly integrate multiple foundation models into a production application without managing model infrastructure. The application requires RAG, guardrails and tool use.


	Keyword:
		multiple FMs
		managed
		no infrastructure management
		RAG
		Guardrails
		tool use

	→ Amazon Bedrock
