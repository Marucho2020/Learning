Lesson 20 -- AIP-C01 --= 5. On-Demand vs Provisioned Throughput (Bedrock) -//



Provisioned Throughput : thông lượng được cung cấp
On-Demand	: theo yêu cầu

Đây là một trong những chủ đề AWS rất thích đưa vào đề Professional vì nó liên quan trực tiếp đến Cost Optimization + Performance + Scalability + SLA. Nếu không hiểu bản chất thì rất dễ bị lừa bởi các đáp án kiểu:

"Provisioned luôn nhanh hơn nên chọn."
"On-Demand rẻ hơn nên dùng."
"Production thì luôn phải Provisioned."

Cả ba đều sai nếu không xét workload.


# I. Bản chất
	Điều đầu tiên phải hiểu:
	Throughput = Khả năng xử lý inference của model.

	Ví dụ:
	Một model Claude có thể xử lý
		1 request
		100 request
		1000 request

	cùng lúc.

	Đó chính là throughput.


Trong Bedrock hiện nay có hai cách mua năng lực inference.

# 1. On-Demand Throughput

	Giống như đi taxi.
	Bạn cần thì gọi.
	Không cần thì thôi.
	AWS sẽ tự tìm máy inference đang rảnh để chạy request.
	Bạn chỉ trả tiền cho request.


	User
	↓
	InvokeModel()
	↓
	AWS Bedrock
	↓
	Tìm inference capacity đang rảnh
	↓
	Model chạy
	↓
	Trả kết quả
	

	Bạn không sở hữu bất kỳ tài nguyên inference nào.
	Bạn chỉ "thuê tạm".



# 2. Provisioned Throughput

	Giống như thuê nguyên một chiếc taxi theo tháng.
	Chiếc taxi đó luôn chờ bạn.
	Không ai dùng chung.

		User
		↓
		Provisioned Throughput
		↓
		Reserved GPU		
		↓
		Foundation Model
		↓
		Response

		AWS reserve sẵn inference capacity cho bạn.
		Dù bạn dùng hay không vẫn trả tiền.



# Ví dụ đời thường

	Nhà hàng
	
	On-Demand
		Bạn đến nhà hàng.
		Nếu còn bàn
		→ ngồi.
		Nếu đông
		→ phải đợi.

	Provisioned
		Bạn đặt phòng VIP.
		Dù hôm nay không tới
		phòng vẫn dành riêng.
		Đó chính là bản chất.





# Điều AWS reserve là gì?
	reserve : dự trữ

	Đây là điểm rất nhiều người hiểu sai.
	Không phải AWS reserve model.
	Model vẫn là Claude.
	Model vẫn giống hệt.
	AWS reserve
	Inference Capacity
	bao gồm
		GPU
		Memory
		Compute
		Token processing capacity

	để model luôn chạy trên tài nguyên dành riêng.




# Vì sao Provisioned nhanh hơn?

	Không phải model nhanh hơn.
	Mà vì
	Bạn không cần xếp hàng.
	Ví dụ
	
	On-Demand

		100 người
		↓
		1 cụm GPU
		↓
		Bạn đứng thứ 98


	Provisioned
		GPU riêng
		↓
		Bạn luôn đứng đầu

	Latency giảm.


#So sánh

|            | On-Demand                        | Provisioned               |
| ---------- | -------------------------------- | ------------------------- |
| Trả tiền   | Theo request                     | Theo giờ / capacity       |
| GPU        | Shared                           | Dedicated                 |
| Queue      | Có thể có                        | Hầu như không             |
| Latency    | Có thể dao động                  | Ổn định                   |
| Throughput | AWS quyết định                   | Bạn đặt trước             |
| Cost       | Thấp nếu ít dùng                 | Rẻ hơn nếu dùng rất nhiều |
| SLA        | Không đảm bảo capacity tuyệt đối | Capacity được reserve     |
| Scale      | AWS tự scale                     | Bạn phải provision        |



# Ví dụ Production



	Một chatbot nội bộ.
		100 nhân viên.
		Mỗi ngày
		300 câu hỏi.
		Không có giờ cao điểm.
		On-Demand đủ.

	Một ngân hàng.
		9:00 sáng.
		20.000 nhân viên login.
		Ai cũng hỏi AI.
		Nếu dùng On-Demand.


		Queue
		↓
		Latency
		↓
		Timeout

	Do đó
	Provisioned.



# Cost

		On-Demand
		Ví dụ

		1000 request
		↓
		100 yen

		Nếu không có request
		0 yen



		Provisioned
		Thuê
			4 GPU
			↓
			24 giờ
			↓
			Vẫn trả tiền

		Dù hôm đó không ai hỏi.
	Đó là trade-off.




# Khi nào Provisioned rẻ hơn?


	Đây là chỗ AWS hay gài.
	Nhiều người nghĩ
	Provisioned luôn đắt.
	Sai.
	Ví dụ
	
	On-Demand
		1 triệu request/ngày
		↓
		100 triệu token


	Lúc này
		AWS tính theo token.
		Có thể vượt rất xa chi phí của một cụm GPU reserve.
		Nghĩa là
		Usage càng ổn định
		Provisioned càng có lợi.




# Autoscaling

	Provisioned không có nghĩa là cố định mãi.
	Bạn vẫn có thể

		2 unit
		↓
		4 unit
		↓
		8 unit

	tùy nhu cầu.
	Nhưng
	không linh hoạt như On-Demand.



# Latency
	On-Demand

		200 ms
		↓
		500 ms
		↓
		1200 ms
	tùy tải hệ thống.


	Provisioned
		210
		↓
		220
		↓
		215
		↓
		230


		Đề Professional rất thích từ khóa:
		Predictable latency		(độ trễ Có thể dự đoán được)
	=> Chọn Provisioned.

# Mapping AWS


| Nhu cầu             | Dùng                                        |
| ------------------- | ------------------------------------------- |
| Demo                | On-Demand                                   |
| Development         | On-Demand                                   |
| PoC                 | On-Demand                                   |
| Internal Tool       | On-Demand                                   |
| Production nhỏ      | On-Demand                                   |
| Production lớn      | Provisioned                                 |
| SLA cao             | Provisioned                                 |
| Latency ổn định     | Provisioned                                 |
| Predictable traffic | Provisioned                                 |
| Flash traffic       | On-Demand (hoặc kết hợp chiến lược phù hợp) |



# Trade-off


| Tiêu chí               | On-Demand   | Provisioned               |
| ---------------------- | ----------- | ------------------------- |
| Cost khi ít request    | ⭐⭐⭐⭐⭐       | ⭐                         |
| Cost khi nhiều request | ⭐⭐          | ⭐⭐⭐⭐                      |
| Latency                | ⭐⭐          | ⭐⭐⭐⭐⭐                     |
| Capacity guarantee     | ⭐           | ⭐⭐⭐⭐⭐                     |
| Vận hành               | Đơn giản    | Phức tạp hơn              |
| Scale                  | AWS quản lý | Bạn lập kế hoạch capacity |
