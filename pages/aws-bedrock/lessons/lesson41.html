# 1. Bản chất của Model Versioning

Hiểu đơn giản:														hiện vật
	Model Versioning = coi mỗi phiên bản model/configuration là một artifact bất biến để có thể theo dõi, so sánh và quay lại phiên bản trước.


	Ví dụ:

		Production
		   │
		   ▼
		Model v1
		   │
		   │ deploy v2
		   ▼
		Model v2


	Sau khi v2 có vấn đề:

	Model v2 ❌
	   │
	   │ rollback
	   ▼
	Model v1 ✅

	Điểm quan trọng:
		Rollback không phải là “train lại model cũ”.
		Model cũ phải được lưu/version hóa ngay từ đầu.


# 2. Tại sao GenAI cần Model Versioning?
	Trong ứng dụng GenAI, output không chỉ phụ thuộc vào model.


Có thể có:
	Model
	+
	Model version
	+
	System prompt
	+
	Inference parameters
	+
	RAG configuration
	+
	Embedding model
	+
	Knowledge base
	+
	Guardrail
	+
	Tool/Agent configuration


	Ví dụ:
		Claude v1
		Temperature = 0.2
		Prompt v3
		Knowledge Base v5
		Guardrail v2

	Sau đó developer thay đổi:
		Claude v2
		Temperature = 0.7
		Prompt v4
		Knowledge Base v6



Output thay đổi.
	Nếu chỉ version hóa model mà không version hóa configuration, bạn có thể không tái tạo được production environment cũ.

	Đây là tư duy reproducibility. (khả năng tái tạo)



# 3. Model Version ≠ Model Alias ≠ Deployment


| Khái niệm      | Bản chất                                      |
| -------------- | --------------------------------------------- |
| Model Version  | Phiên bản artifact/model                      |
| Deployment     | Đưa một version vào môi trường chạy           |
| Alias/Endpoint | Tên logical trỏ tới version đang được sử dụng |
| Rollback       | Chuyển traffic về version ổn định trước       |


	Ví dụ:
		production-model
			   │
			   ▼
			Model v2

	Rollback:
		production-model
			   │
			   ▼
			Model v1

	Application không nhất thiết phải thay đổi code.

# 5. SageMaker Model Versioning

	Với custom model, SageMaker phù hợp hơn cho lifecycle control.
	

	Training
	   │
	   ▼
	Model Artifact
	   │
	   ▼
	SageMaker Model Registry
	   │
	   ├── v1
	   ├── v2
	   └── v3
			  │
			  ▼
		   Approval
			  │
			  ▼
		  Deployment



	Ví dụ:

	Model Registry

		 ├── 1.1 → Staging

	Nếu 1.2 fail:
		Production
			│
			▼
		   1.0



# 6. Rollback Strategy quan trọng nhất (Strategy : chiến lược)

Có 4 pattern cần nhớ.

# Strategy 1 — Blue/Green
	
			
		Đây là pattern rất quan trọng.

						┌── Model v1
		User ──► Traffic│
						└── Model v2

		Ví dụ:
			Blue  = v1
			Green = v2
			v2 được deploy độc lập.

		Sau đó kiểm tra:
			v2
			│
			├── latency
			├── error rate
			├── accuracy
			├── hallucination
			└── safety

		Nếu tốt:
			100% → v2

		Nếu xấu:
			100% → v1
			
		Ưu điểm
			rollback nhanh
			giảm downtime
			production version vẫn tồn tại
			dễ kiểm thử trước khi chuyển traffic
			
		Nhược điểm
			Tốn resource hơn vì phải duy trì hai version.	
			
			
			
	
# 7. Canary Deployment

	Canary không chuyển 100% traffic ngay.

		
	Ví dụ:
		v1 = 95%
		v2 = 5%

	Sau một thời gian:
		v1 = 80%
		v2 = 20%

	Sau đó:
		v1 = 50%
		v2 = 50%

	Cuối cùng:
		v2 = 100%

	Nếu phát hiện:
		Error ↑
		Latency ↑
		Quality ↓

	thì:
		v2 = 0%
		v1 = 100%
		Khi nào tốt?
		Khi muốn giảm blast radius.

	Ví dụ:
		Model mới có thể ảnh hưởng đến 10 triệu request/ngày.

	Không nên:

		10 million requests
			   ↓
			  v2

	Mà:
		9.5M → v1
		0.5M → v2

	Nếu v2 có bug thì chỉ một phần traffic bị ảnh hưởng.
		
		
	
	
# 8. A/B Testing

	A/B testing khác Canary ở mục đích.



	Canary

	Mục tiêu:
		Deployment safety
		A/B Testing

	Mục tiêu:
		So sánh behavior/performance giữa hai version

	Ví dụ:

		Users A → v1
		Users B → v2


	| Metric            |    v1 |    v2 |
	| ----------------- | ----: | ----: |
	| Accuracy          |   88% |   91% |
	| Latency           | 500ms | 650ms |
	| Cost              |     $ |    $$ |
	| User satisfaction |   4.1 |   4.4 |


	v2 có accuracy cao hơn nhưng latency/cost cao hơn.

	Khi đó decision không đơn giản là:
		v2 tốt hơn.
		Mà phải xét business requirements và trade-off.




# 9. Rollback phải bao gồm cả Configuration


	Đây là một trap cực mạnh.

	Giả sử:
	v1:
		Model = Claude
		Prompt = P1
		Temperature = 0.2
		RAG = KB1
		Guardrail = G1

	v2:
		Model = Claude
		Prompt = P2
		Temperature = 0.7
		RAG = KB2
		Guardrail = G2

	Nếu chỉ rollback:
		Model v2 → Model v1

	nhưng vẫn giữ:

		Prompt P2
		KB2
		Guardrail G2

	thì:
		Bạn chưa thực sự rollback production state.

	Production state nên được coi là:

		Release =
			Model
		  + Prompt
		  + Parameters
		  + RAG
		  + Guardrail
		  + Application code



# 10. GenAI đặc biệt khó rollback vì RAG
	Đây là điểm Senior/Professional-level rất thích.



	Giả sử:

		Model v1
			+

	Sau đó:

		Model v2
			+
		Knowledge Base v2
		v2 gây hallucination.

	Bạn rollback model:
		Model v1

	nhưng KB đã thay đổi:
		KB v2

	Output vẫn có thể khác.
		Vì vậy cần version/control cả:

		Model
		Prompt
		Embedding
		Chunking strategy
		Vector index
		Documents
		Retrieval parameters
		Guardrail




# 11. Embedding Model cũng phải version hóa 

	Ví dụ:
		Embedding v1
			↓
		Vector DB

	sau đó đổi:
		Embedding v2

		Bạn không nên đơn giản đưa embedding v2 vào cùng index cũ nếu dimension/semantic space không tương thích.

	Thường cần:

		Documents
			│
			├── Embedding v1 → Index v1
			│
			└── Embedding v2 → Index v2

	Sau đó test:
		Retriever v1 + Model v1
		Retriever v2 + Model v2

	Đây chính là tư duy versioned RAG pipeline.




# 12. Rollback trong Agentic AI

	Agent còn phức tạp hơn.
	
	Một Agent release có thể gồm:

		Foundation Model
			  +
		System Prompt
			  +
		Action Groups
			  +
		Lambda
			  +
		Knowledge Base
			  +
		Guardrail
			  +
		Agent configuration


	Ví dụ:
		Agent v3
		 ├── Claude model v2
		 ├── Prompt v5
		 ├── Lambda v4
		 ├── KB v3
		 └── Guardrail v2

	Nếu Agent v3 lỗi, rollback phải xác định release artifact nào cần quay lại, không chỉ model.


# 13. Immutable Deployment

Một nguyên tắc rất quan trọng:
	Đừng sửa trực tiếp production version. Hãy tạo version mới.

		Không tốt:
			Production v1
				↓
			modify
				↓
			Production v1

		Tốt:
			Production v1
				  │
				  └── clone/change
						  ↓
					  Production v2

		Lợi ích:
			reproducibility
			auditability
			rollback
			debugging
			compliance

# 15. Automated Rollback

	Production không nên phụ thuộc hoàn toàn vào con người.
	Ví dụ:

		Deploy v2
			↓
		Canary 5%
			↓
		CloudWatch metrics
			↓
		Error rate > threshold?
			   │
		   ┌───┴───┐
		  Yes      No
		   │        │
		Rollback   Continue
		   │        │
		 v1       25%


	Ví dụ policy:

		IF
		  error_rate > 2%
		OR
		  p95_latency > 2 sec
		OR
		  safety_violation > threshold
		THEN
		  rollback


	Với GenAI còn có thể thêm:

		evaluation_score < threshold



# 16. Nhưng có một vấn đề: Quality không phải lúc nào cũng đo realtime được
	Đây là chỗ Professional-level bắt đầu khó.

	Infrastructure metrics:
	
		CPU
		Memory
		Latency
		5xx
	dễ đo.
	
	GenAI quality:
		Hallucination
		Faithfulness
		Helpfulness
		Reasoning quality	

	khó hơn.
		Vì vậy một hệ thống production tốt thường kết hợp:

			Operational Metrics
					+
			Model Evaluation
					+
			Business Metrics
					+
			Safety Metrics

		Không nên chỉ rollback dựa trên HTTP 500.


# Không nên chỉ rollback dựa trên HTTP 500.

| Strategy   | Mục tiêu         | Rollback   | Cost       | Blast Radius |
| ---------- | ---------------- | ---------- | ---------- | ------------ |
| Blue/Green | Safe deployment  | Rất nhanh  | Cao        | Thấp         |
| Canary     | Gradual rollout  | Rất nhanh  | Trung bình | Rất thấp     |
| A/B        | So sánh version  | Có         | Trung bình | Có kiểm soát |
| Big Bang   | Deploy ngay 100% | Khó/rủi ro | Thấp       | Rất cao      |



	Nếu đề hỏi:
		Production system, zero/minimal downtime, ability to quickly revert.

	Thường nghĩ:
		Blue/Green

	Nếu đề nhấn mạnh:
		Gradually expose users and minimize impact if new model is defective.

	Nghĩ:
		Canary

	Nếu đề nhấn mạnh:
		Compare user behavior/business performance between two models.

	Nghĩ:
		A/B testing



# 18. AWS Exam Trap 



Trap 1
	“Rollback model bằng cách retrain model cũ.”
	❌ Sai.
	Rollback cần version artifact đã tồn tại.

Trap 2
	“Chỉ cần version model.”
	❌ Không đủ đối với GenAI production.
	
	Cần xem:
		Model
		Prompt
		Parameters
		RAG
		Embedding
		Guardrail
		Tools
		Application
		
		
	Trap 3

		“Canary = A/B testing.”
		❌ Không giống nhau.

		Canary → deployment safety
		A/B     → comparison/experimentation


	Trap 4
		“Blue/Green luôn rẻ nhất.”
		❌ Sai.
		Blue/Green thường yêu cầu duy trì environment/version song song.


	Trap 5
		“Rollback model là rollback toàn bộ GenAI system.”
		❌ Sai.
		RAG, prompt, guardrail, Lambda, tool configuration... có thể vẫn ở version mới.


	Trap 6
		“Model mới accuracy cao hơn → deploy ngay.”
		❌ Đây là bẫy.
		Phải xét:
			Accuracy
			Latency
			Cost
			Safety
			Reliability
			Business KPI

	Một model accuracy tăng 2% nhưng cost tăng 5× và latency tăng 3× có thể không phải lựa chọn tốt hơn.


Keyword trong đề


| Keyword trong đề              | Nghĩ ngay                          |
| ----------------------------- | ---------------------------------- |
| gradually release             | Canary                             |
| limited percentage of traffic | Canary                             |
| minimize blast radius         | Canary                             |
| instant/quick rollback        | Blue/Green / versioned deployment  |
| two environments              | Blue/Green                         |
| compare user groups           | A/B                                |
| experiment                    | A/B                                |
| immutable artifact            | Versioning                         |
| reproducibility               | Versioning                         |
| automated rollback            | Monitoring + deployment automation |
| model quality degradation     | Evaluation                         |
| zero/minimal downtime         | Blue/Green                         |
