# 1. Định nghĩa bản chất

| SQL                                                | NoSQL                                                            |
| -------------------------------------------------- | ---------------------------------------------------------------- |
| Lưu dữ liệu theo **bảng (Table)** gồm hàng và cột. | Lưu dữ liệu theo nhiều kiểu: Key-Value, Document, Column, Graph. |
| Có Schema cố định.                                 | Schema linh hoạt hoặc gần như không có Schema.                   |
| Quan hệ giữa các bảng bằng JOIN.                   | Thường không JOIN, dữ liệu được thiết kế để truy cập trực tiếp.  |



		# Nói bản chất

		Đừng nhớ:
			SQL = Database quan hệ.

		Hãy nhớ:
			SQL được sinh ra để đảm bảo dữ liệu luôn chính xác.

		Ví dụ

		Ngân hàng

			Khách hàng
			↓

			Tài khoản
			↓

			Giao dịch
			↓

			Lịch sử

		Nếu một giao dịch sai chỉ 1 đồng cũng không được.

				Cho nên SQL ưu tiên

				Consistency  tính nhất quán 
				Transaction  tính giao dịch 
				Integrity	 tính chính xác 
				
				
	Ngược lại
		NoSQL được sinh ra để giải quyết vấn đề khác.
		Không phải:
		"thay thế SQL"

		Mà là
			Scale cực lớn và tốc độ cực cao.
			Ví dụ
			Facebook
			Instagram
			TikTok
			Amazon Shopping

		Một ngày			
				
			Like
			Comment
			View
			Log
			Session
			Recommendation				
							
			hàng tỷ record.

			Nếu cứ JOIN liên tục thì chết.
				Cho nên NoSQL chấp nhận
				Dữ liệu lặp
				Không JOIN
				Schema thay đổi liên tục
			để đổi lấy
			tốc độ
			khả năng scale

# 6. Trade-off

| SQL              | NoSQL              |
| ---------------- | ------------------ |
| Data chính xác   | Scale tốt          |
| JOIN mạnh        | Không JOIN         |
| Transaction mạnh | Throughput cao     |
| Schema cố định   | Schema linh hoạt   |
| Query phức tạp   | Query đơn giản     |
| Vertical Scaling | Horizontal Scaling |

# 13. Kết luận cần nhớ để thi

	SQL (RDS/Aurora): ưu tiên tính chính xác, ACID, JOIN, quan hệ dữ liệu, báo cáo phức tạp.
	NoSQL (DynamoDB): ưu tiên khả năng mở rộng, throughput cao, độ trễ thấp, schema linh hoạt, không phụ thuộc JOIN.
	Trong kiến trúc thực tế, rất nhiều hệ thống dùng cả SQL và NoSQL (polyglot persistence), mỗi loại đảm nhiệm phần dữ liệu phù hợp.
