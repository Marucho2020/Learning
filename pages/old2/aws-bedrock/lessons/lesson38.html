Lesson 38 -- AIP-C01 --= Distillation (Model Distillation trên Bedrock) -//

Distillation : chưng cất 
	Đây là một chủ đề rất đáng chú ý cho AIP-C01, vì nó liên quan trực tiếp đến bài toán model selection + cost + latency + production optimization.


# 1. Bản chất của Model Distillation
	Distillation = dùng một model lớn/giỏi (Teacher) để tạo dữ liệu/kiến thức hành vi cho một model nhỏ hơn (Student), sau đó huấn luyện Student để nó bắt chước Teacher.


Ví dụ:

             Teacher Model
          (mạnh, lớn, đắt)
                  │
                  │ generate responses
                  ▼
          Training / Distillation Data
                  │
                  ▼
             Student Model
          (nhỏ, nhanh, rẻ)


		Mục tiêu không phải là làm Student giống kiến trúc Teacher.
	Mục tiêu là:
	
		Student đạt được chất lượng gần Teacher nhưng với inference cost và latency thấp hơn.


	Ví dụ:
		Teacher: Claude Sonnet
		Student: một model nhỏ hơn
		Ứng dụng có 10 triệu request/tháng

	Nếu Student đạt 95% chất lượng nhưng inference rẻ hơn rất nhiều, production có thể chuyển phần lớn traffic sang Student.




# 2. Vì sao cần Distillation?

	Giả sử bạn xây chatbot cho doanh nghiệp.

	Ban đầu:

		User
		  ↓
		Large Foundation Model
		  ↓
		Excellent answer

	Nhưng production xuất hiện vấn đề:
		model lớn → expensive
		latency cao
		throughput thấp hơn
		không cần năng lực reasoning quá mạnh cho những request đơn giản

	Ví dụ 90% request chỉ là:

	"Giờ làm việc của công ty?"
	"Chính sách hoàn tiền là gì?"
	"Làm sao reset password?"

	Dùng model cực mạnh cho tất cả request là overkill.


	Có thể làm:

							 ┌── simple request ──→ Student
			User → Router ───┤
							 └── complex request ─→ Teacher

	Hoặc sau khi distillation đủ tốt:
		User
		  ↓
		Student Model
		  ↓
		95% request xử lý được

	Teacher chỉ được dùng cho những trường hợp khó.




# 3. Distillation khác Fine-tuning như thế nào?

|                    | Fine-tuning                   | Distillation                         |
| ------------------ | ----------------------------- | ------------------------------------ |
| Mục tiêu           | Adapt model cho task/domain   | Làm model nhỏ bắt chước model lớn    |
| Teacher bắt buộc?  | Không                         | Có                                   |
| Dataset            | Human-labeled/domain data     | Thường có dữ liệu/outputs từ Teacher |
| Student            | Có thể cùng hoặc khác model   | Thường là model nhỏ hơn              |
| Mục tiêu chính     | Accuracy/domain adaptation    | Cost + latency + efficiency          |
| Ví dụ              | Model học terminology ngành y | Small model học behavior của Claude  |
| Production benefit | Specialized capability        | Cheaper/faster inference             |


	Cách nhớ

	Fine-tuning:
		"Tôi muốn model học thêm cái này."

	Distillation:
		"Tôi muốn model nhỏ học cách model lớn trả lời."




# 4. Distillation không phải là "copy knowledge" đơn giản

	Đây là điểm cần hiểu sâu.
	Teacher không đơn giản đưa toàn bộ internal knowledge sang Student.
	
	Thông thường Student học từ signals do Teacher cung cấp, chẳng hạn:
		Input
		  ↓
		Teacher
		  ↓
		Teacher output / labels / signals
		  ↓
		Student training
		
			
	Ví dụ:

	Question:
		"Customer muốn refund sau 45 ngày?"

	Teacher:
		"Không được refund vì policy chỉ cho phép trong 30 ngày."

	Student được train để học pattern:
		Input → appropriate answer

	Do đó Student có thể bắt chước behavior của Teacher mà không cần chứa nguyên Teacher bên trong.

# 6. Một scenario kiểu AIP-C01

Giả sử:

	Một công ty đang sử dụng foundation model lớn để xử lý customer-support requests. Model có accuracy rất tốt nhưng inference cost cao và latency không đáp ứng SLA. Công ty muốn giữ chất lượng tương tự nhưng sử dụng model nhỏ hơn.


A. RAG

	→ Sai hướng.
	RAG giúp model truy cập external/private knowledge, không trực tiếp giải quyết việc model quá lớn và đắt.

B. Fine-tuning Student model bằng dữ liệu của Teacher
	→ Có thể đúng tùy wording.

C. Model Distillation
	→ Đáp án mạnh nhất nếu đề nhấn mạnh việc transfer behavior/capability từ large Teacher sang smaller Student nhằm giảm cost/latency.

D. Tăng temperature
	→ Hoàn toàn sai hướng.



# 7. Trap cực kỳ quan trọng


	Trap 1 — Distillation ≠ RAG

		RAG:
			Model
			  +
			External knowledge

		Distillation:
			Large Teacher
				  ↓
			Smaller Student


	Nếu đề nói:
		"The model lacks access to frequently changing company data"
		→ nghĩ RAG.

	Nếu đề nói:
		"The model is too expensive/slow"
		→ nghĩ distillation / smaller model / model selection.






	Trap 2 — Distillation ≠ Prompt Engineering 

		Prompt engineering:
			Same model
			+
			Better prompt

		Distillation:
			Teacher
			 ↓
			Student training

		Nếu chỉ thay đổi prompt mà không training Student → không phải distillation.




	Trap 3 — Distillation không đảm bảo Student tốt bằng Teacher

		Đây là trade-off thực tế.

			Teacher:
				Accuracy       ██████████ 100%
				Cost           ██████████

			Student:
				Accuracy       █████████  ~90-98%
				Cost           ███
				Latency        ██

		Bạn đang đổi một phần capability lấy efficiency.

		Không có chuyện:
			"Student nhỏ hơn nhưng luôn giữ 100% capability của Teacher."
			Nếu requirement là maximum accuracy, Teacher có thể vẫn phù hợp.

		Nếu requirement là:
			"good enough + massive scale + low latency + low cost"
			→ Student + distillation rất hấp dẫn.




# 8. Khi nào KHÔNG nên dùng Distillation? 

	Ví dụ:
		Model cần trả lời những câu hỏi cực kỳ phức tạp, reasoning dài, thay đổi liên tục và yêu cầu accuracy tối đa.
		Distillation có thể không phải lựa chọn tốt nhất.

	Bởi vì:
		Teacher capability
			   ↓
		Student approximation

		Student có nguy cơ mất một phần capability.
		Ngoài ra, nếu vấn đề thực sự là knowledge freshness, distillation không giải quyết bản chất.

	Ví dụ:

		Company policy thay đổi mỗi ngày
		Không nên liên tục distill model chỉ để cập nhật policy.
		→ RAG phù hợp hơn.





# 9. Distillation + RAG có thể kết hợp
	Đây mới là architecture production đáng chú ý.

                 User
                   │
                   ▼
              Application
                   │
                   ▼
              RAG Retrieval
                   │
             relevant context
                   │
                   ▼
             Student Model
                   │
                   ▼
                Answer

	Student được distill để:
		hiểu task tốt
		trả lời theo style của Teacher
		giảm latency
		giảm cost

	RAG chịu trách nhiệm:
		fresh knowledge
		private company data
		documents
		policies

	Hai thứ giải quyết hai vấn đề khác nhau.


# 10. So sánh toàn bộ các kỹ thuật dễ nhầm


| Kỹ thuật               | Giải quyết vấn đề gì?          | Key idea                          |
| ---------------------- | ------------------------------ | --------------------------------- |
| Prompt Engineering     | Model trả lời chưa tốt         | Better instruction                |
| RAG                    | Thiếu external/fresh knowledge | Retrieve context                  |
| Fine-tuning            | Model cần specialize           | Train model trên task/domain data |
| Continued Pre-training | Model cần học domain/corpus    | Continue pre-training             |
| Distillation           | Model quá lớn/đắt/chậm         | Teacher → smaller Student         |
| Model Selection        | Chọn model phù hợp             | Choose right FM                   |
| Quantization           | Model inference quá nặng       | Lower numerical precision         |




Câu hỏi trong đầu khi đọc đề:

	Thiếu knowledge?
		   ↓
		  RAG


	Cần specialize?
		   ↓
		Fine-tuning


	Cần học thêm domain/corpus lớn?
		   ↓
	Continued Pre-training


	Model quá đắt / latency cao?
		   ↓
	Distillation / smaller model / optimization


	Chỉ prompt chưa tốt?
		   ↓
	Prompt Engineering


	Model inference quá nặng về compute/memory?
		   ↓
	Quantization



# 11. Từ khóa AIP-C01 cần nhìn thấy là phản xạ


	Nếu đề xuất hiện:
		Teacher model
		Student model
		knowledge transfer
		model compression
		smaller model
		reduce inference cost
		reduce latency
		maintain comparable quality
		high-volume inference
		production efficiency
		large model → small model

	→ DISTILLATION

	Đặc biệt:
		Teacher → Student + lower cost/latency
		là pattern cực mạnh.

Team muốn giảm inference cost và latency trong khi vẫn giữ output quality gần với model hiện tại. Giải pháp nào phù hợp nhất?

	AWS đang kiểm tra bạn có phân biệt:
		RAG
		Fine-tuning
		Distillation
		Model selection
		Prompt engineering

	chứ không kiểm tra việc bạn thuộc definition.


	Bẫy "nghe đúng"
		"Fine-tune the largest model with more data."
		Nghe rất hợp lý vì muốn accuracy cao.

	Nhưng nếu requirement chính là:
		lower inference cost + lower latency
		thì đây có thể là đáp án sai.

	Professional exam luôn bắt bạn nhìn constraint chính, không phải chọn giải pháp "mạnh nhất".
