Lesson 27 -- Stream -//



# 1. Streams Là Gì? (What are Streams?)
	Định nghĩa: Streams là cách xử lý dữ liệu theo chunks (miếng nhỏ), thay vì load toàn bộ vào memory. Giống như dòng chảy dữ liệu: đọc/ghi dần dần, không chờ hết. Không phải array/buffer lớn, mà là sequence of data over time.


	## Tại Sao Dùng Streams? (Why Use Streams?)
		- Memory Efficiency: Xử lý file 10GB trên server 1GB RAM – chỉ load chunk 64KB/lần.
		- Time Efficiency: Bắt đầu process ngay (e.g., stream video: xem ngay không chờ download hết).
		- Composability: Kết nối streams thành pipeline (e.g., read file → compress → write).
		- Better UX: Real-time data (e.g., HTTP streaming responses).	

	Sâu sắc: Trong production (e.g., Netflix-like apps), streams giảm latency và CPU. Năm 2025, với edge computing (Vercel/Cloudflare), streams tích hợp tốt với Web APIs cho serverless.

	Ví dụ Basic (copy file dùng streams):

const fs = require('fs');
const readable = fs.createReadStream('input.txt', 'utf8');
const writable = fs.createWriteStream('output.txt');
readable.pipe(writable);  // Magic: tự động copy!
writable.on('finish', () => console.log('Done!'));
readable.on('error', err => console.error(err));
writable.on('error', err => console.error(err));


# 2. Core Stream Types
	Node.js có 4 loại streams chính, tất cả kế thừa EventEmitter:

Type,Mô tả,Examples
Readable,Đọc data từ source (push data ra),"fs.createReadStream, process.stdin, http.IncomingMessage"
Writable,Ghi data vào destination (pull data vào),"fs.createWriteStream, process.stdout, http.ServerResponse"
Duplex,Cả read & write (two-way),"net.Socket (TCP), zlib (compress/decompress)"
Transform,"Duplex nhưng transform data (e.g., compress)","zlib.createGzip, crypto.createCipher"

	Sâu: Readable/Writable là base; Duplex/Transform là specialized. Năm 2025, dùng pipeline() (từ stream.promises) cho async handling.



# 3. Events Trong Streams
	Streams emit events để control flow:


Event,Type,Mô tả
'data',Readable,Chunk mới sẵn sàng (pause/resume flow)
'end',Readable,Hết data
'error',All,Lỗi xảy ra
'finish',Writable,Đã ghi hết
'drain',Writable,"Buffer empty, có thể write tiếp"
'pipe',Readable,Được pipe vào writable


	## Ví dụ Readable:

const fs = require('fs');
const stream = fs.createReadStream('file.txt');
stream.on('data', chunk => console.log(chunk.toString()));  // Chunk là Buffer
stream.on('end', () => console.log('Done'));
stream.on('error', err => console.error(err));

	Backpressure: Nếu writable chậm, readable pause tự động – tránh overflow.



# 4. Piping Streams
	pipe(): Kết nối readable → writable, tự handle flow/backpressure.
	
	readable.pipe(transform).pipe(writable);  // Pipeline: read → transform → write

	## Ví dụ Compress File: 
	
const fs = require('fs');
const zlib = require('zlib');
fs.createReadStream('input.txt')
  .pipe(zlib.createGzip())  // Transform: compress
  .pipe(fs.createWriteStream('input.txt.gz'));
  
  
	## Async Pipeline (Node 15+): 
const { pipeline } = require('stream/promises');
await pipeline(readable, transform, writable);  // Handle errors cleanly	
	
	Sâu: Pipeline tốt cho ETL (Extract-Transform-Load) như process logs: read → filter → write DB.
	
	
# 	5. Custom Streams (Advanced)
	Tạo Readable/Writable custom bằng extend class.
	Custom Readable (push data manually):

const { Readable } = require('stream');
class RandomNumberStream extends Readable {
  constructor(options) {
    super(options);
    this._max = 10;
    this._index = 0;
  }
  _read(size) {
    if (this._index++ < this._max) {
      this.push(Math.random().toString());
    } else {
      this.push(null);  // End stream
    }
  }
}
const stream = new RandomNumberStream();
stream.on('data', num => console.log(num));



	##	Custom Transform (upper case text):
	
const { Transform } = require('stream');
class UpperCaseTransform extends Transform {
  _transform(chunk, encoding, callback) {
    this.push(chunk.toString().toUpperCase());
    callback();
  }
}
process.stdin.pipe(new UpperCaseTransform()).pipe(process.stdout);

	Sâu: Dùng cho custom pipelines (e.g., real-time data processing trong IoT).




# 6. Real-World Examples

	## HTTP Streaming (video server):
	
	
const http = require('http');
const fs = require('fs');
http.createServer((req, res) => {
  const stat = fs.statSync('video.mp4');
  res.writeHead(200, { 'Content-Length': stat.size, 'Content-Type': 'video/mp4' });
  fs.createReadStream('video.mp4').pipe(res);  // Stream trực tiếp
}).listen(3000);


	## Processing Large CSV (dùng csv-parser):
	
const fs = require('fs');
const csv = require('csv-parser');  // npm i csv-parser
const results = [];
fs.createReadStream('large.csv')
  .pipe(csv())
  .on('data', row => results.push(row))
  .on('end', () => console.log(results.length));
	
	
# 	7. Best Practices
	
	- Error Handling: Luôn on('error') cho tất cả streams.
	- Dùng pipeline(): Tự cleanup nếu error.
	- Backpressure: Kiểm tra writable.write() return false → chờ 'drain'.
	- End Streams: Gọi end() cho writable khi done.
	- Avoid Sync: Không sync ops trong handlers (block Event Loop).
	- Buffer Size: Set highWaterMark cho custom (default 64KB readable, 16KB writable).
	- Warning: Không handle 'error' → crash app. Memory leaks nếu không destroy streams.Common Pitfalls: Quên pause/resume → overflow; pipe multiple writables → data duplicate.
