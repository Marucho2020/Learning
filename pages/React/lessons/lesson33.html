Lesson 33 -- useContext -//


#  Khái niệm 

	Context quản lý state toàn cục, cho phép component con access state mà không truyền props qua từng lớp. Useful khi state shared giữa nhiều branches trong component tree.
	
	Insight chuyên gia: Context là provider-consumer pattern, không phải pub-sub (không notify changes tự động như observables). State thay đổi → Provider re-render → tất cả consumers re-render (shallow). Optimize bằng React.memo cho consumers hoặc split Contexts (ví dụ: separate UserContext và ThemeContext).
	

	Insight chuyên gia: Context lý tưởng cho theming, authentication, hoặc user data (không thay đổi thường xuyên), nhưng không phải state management full-featured – nếu state update thường, có thể gây re-renders thừa (vì Provider re-render lan tỏa). Trong React 18+, Context hỗ trợ Concurrent Rendering tốt hơn. Nhược điểm: Overuse dẫn đến "context hell" (nhiều Providers nested); best practice: Kết hợp với useReducer cho state complex, hoặc Zustand/MobX cho global store. Alternative: Prop drilling ổn cho small apps; Context cho medium; Redux/Recoil cho large-scale. Trong SSR (Next.js), Context cần hydrate cẩn thận để tránh mismatch.




# 2. The Problem: Prop Drilling 

	State ở parent cao nhất, nhưng nếu component bottom cần, phải truyền qua intermediates (prop drilling) – làm code verbose, khó maintain, đặc biệt deep nesting.

import { useState } from 'react';  // Import useState
import { createRoot } from 'react-dom/client';  // Render root

function Component1() {
  const [user, setUser] = useState("Linus");  // State ở parent

  return (
    <>
      <h1>{`Hello ${user}!`}</h1>
      <Component2 user={user} />  // Truyền prop
    </>
  );
}

function Component2({ user }) {  // Intermediate không cần user
  return (
    <>
      <h1>Component 2</h1>
      <Component3 user={user} />  // Tiếp tục truyền
    </>
  );
}

function Component3({ user }) {  // Consumer cần user
  return (
    <>
      <h1>Component 3</h1>
      <h2>{`Hello ${user} again!`}</h2>  // Sử dụng
    </>
  );
}

createRoot(document.getElementById('root')).render(
  <Component1 />
);

	useState("Linus"): State ở Component1.
	user={user}: Truyền qua Component2 (không dùng) đến Component3.
	Vấn đề: Nếu thêm layers, props chain dài; thay đổi type → update tất cả intermediates.


	Insight chuyên gia: Prop drilling OK cho 2-3 levels, nhưng >5 levels → refactor sang Context. Trong large apps, drilling gây tight coupling; Context loose coupling hơn. Debug: Sử dụng React DevTools để trace props flow.


# 3. The Solution: Create Context

	Tạo Context object với createContext(), sau dùng Provider để wrap tree và provide value.
	
	import { useState, createContext, useContext } from 'react';  // Import cần thiết
	import { createRoot } from 'react-dom/client';

	const UserContext = createContext();  // Tạo Context (default value optional)
	
	createContext(): Trả về object với Provider và Consumer. Default value (nếu không Provider) có thể truyền: createContext(defaultValue).
	Tên convention: PascalCase + "Context".
	
Insight chuyên gia: Default value useful cho testing hoặc optional Contexts. Trong TypeScript, khai báo types: createContext<UserType | undefined>(undefined) để type-safe. Best practice: Export Context từ file riêng (ví dụ: contexts/UserContext.js) để reuse.


# 4. Context Provider 	
	
	Wrap components cần access với <Context.Provider value={...}>, cung cấp value (có thể state, functions, objects).	
	
function Component1() {
  const [user, setUser] = useState("Linus");  // State

  return (
    <UserContext.Provider value={user}>  // Provide value
      <h1>{`Hello ${user}!`}</h1>
      <Component2 />  // Không cần truyền prop
    </UserContext.Provider>
  );
}
value={user}: Value có thể dynamic (state, computed). Update value → re-render consumers.
Wrap chỉ tree cần (không toàn app để tránh unnecessary re-renders).
	
	Insight chuyên gia: Value là object để pass multiple items: value={{ user, setUser }} (cho update từ con). Nhưng nếu value thay đổi thường, memoize với useMemo để stable reference: const value = useMemo(() => ({ user, setUser }), [user]). Performance: Provider ở root (như _app.js trong Next.js) cho global access.



# 5. Use the useContext Hook

	Trong component con, dùng useContext(Context) để access value.

import { useState, createContext, useContext } from "react";  // Import useContext

function Component3() {
  const user = useContext(UserContext);  // Access value

  return (
    <>
      <h1>Component 3</h1>
      <h2>{`Hello ${user} again!`}</h2>
    </>
  );
}


	useContext(UserContext): Trả về current value từ Provider gần nhất (hoặc default nếu không).
	Useful trong deep components mà không drilling.

	Insight chuyên gia: useContext là Hook, tuân thủ rules (top level, functional components). Nếu Context undefined, error – dùng optional chaining hoặc check. Trong class components, dùng <Context.Consumer>. Best practice: Tạo custom Hook để encapsulate: function useUser() { return useContext(UserContext); } – dễ test, reuse.



# 6. Full Example: Ví dụ đầy đủ

	Kết hợp tất cả: Create Context, Provider ở parent, useContext ở con.	


import { useState, createContext, useContext } from 'react';  // Imports
import { createRoot } from 'react-dom/client';

const UserContext = createContext();  // Create

function Component1() {
  const [user, setUser] = useState("Linus");

  return (
    <UserContext.Provider value={user}>  // Provide
      <h1>{`Hello ${user}!`}</h1>
      <Component2 />
    </UserContext.Provider>
  );
}

function Component2() {
  return (
    <>
      <h1>Component 2</h1>
      <Component3 />
    </>
  );
}

function Component3() {
  const user = useContext(UserContext);  // Consume

  return (
    <>
      <h1>Component 3</h1>
      <h2>{`Hello ${user} again!`}</h2>
    </>
  );
}

createRoot(document.getElementById('root')).render(
  <Component1 />
);



	Không prop drilling: Component2 không chạm user.
	Update setUser ở Component1 → auto update Component3.

	## Insight chuyên gia: Để update từ con, pass setter trong value: value={{ user, setUser }}. Ví dụ mở rộng với reducer:

	const [state, dispatch] = useReducer(reducer, initialState);
	<UserContext.Provider value={{ state, dispatch }}>
